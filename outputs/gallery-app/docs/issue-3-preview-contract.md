# Issue #3: 連写の表示と事前準備

2026-10-25 JST。採用したユーザー要件: 先頭写真を先に表示、読み込み状態と総枚数の可視化、充電を条件にしない非閲覧中の事前生成。

## 契約

- 連写を開いた直後は選択写真の大画像だけを要求する。描画後にサムネイルを1枚ずつ要求する。選択変更時は次のサムネイルを待たせ、大画像を優先する。既に実行中の1件は中断しない。
- 現在位置/総枚数は常時表示。各サムネイルは番号（待機）、スピナー（読込）、写真（成功）、!（失敗）を示す。失敗時は下側に再試行。画面世代と要求IDが変わった結果を反映しない。
- UI相談先: Claudeの既存「Loupe ギャラリーアプリ UI/UX」セッション cse_01D3x8Tp12T2E2DQpfC1CoVY。今回の返答の配置・文言・状態表示を採用。2枚同時ロード/全枚完了まで順位操作を禁止する追加提案は、今回の原因と既存操作を考慮して採用せず。
- 端末内のfile / MediaStore / externalstorage providerの写真だけをOSジョブで事前生成。原本のダウンロード・変更、順位/タグ変更は行わない。
- Activity表示中は新しい事前生成を開始しない。実行中の1枚は完了させる。起動/終了境界と各生成開始終了を記録する。
- 縮小画像はfiles/prepared-previewsに保持。従来256MiB LRU対象から分離。既存キャッシュは再生成せず移動して利用。索引から消えた写真/旧バージョンの派生画像は非閲覧時に整理。原本は触らない。
- 空き容量1GiB未満では事前生成を停止。OSの制約・終了で中断しても次回は存在する画像を飛ばして再開。設定で準備済み/対象数・失敗数・停止理由を表示。進捗は直近の背景パスの集計であり、閲覧中の生成による増分は次回集計時に反映。
- 新規写真は索引更新ジョブまたはアプリを閉じた後の次のパスで処理。OSによる実行延期があり、終了直後の開始時刻は保証しない。
