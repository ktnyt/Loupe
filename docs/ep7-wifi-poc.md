# E-P7 Wi-Fi転送PoC

## 目的と範囲

E-P7のWi-Fi転送がLoupeで実用になるか、Androidで一覧・オリジナルの取得と転送時間を確認する。写真の差分自動取り込みに向けた第一段階であり、実験画面から明示的に操作する。

- 機能: カメラのDCIMを走査し、JPEG・ORFを1枚ずつ試験転送する。
- 要件: カメラオリジナルと既存USB取り込み履歴を保持し、転送・保存を確認できたファイルだけ成功として扱う。
- 状態: #121の実装前契約を具体化した仮実装。E-P7実機で一覧取得、JPEG/ORFの少量転送・保存読戻し、背景移行による中止と再試行を確認済み。共通履歴と自動取り込みは後続工程。
- 参照: [USB取り込み](camera-import-contract.md)、[Material 3 UI契約](material3-ui.md)。

## 契約

- 不変条件: 宛先はHTTPの `192.168.0.10`。端末で利用可能なWi-Fiが一つのときにそのNetworkへ通信を束縛し、プロキシとHTTPリダイレクトは使わない。他の宛先の平文通信は許可しない。カメラへの削除・時刻設定・モード変更コマンドは送らない。
- 事前条件: 利用者がAndroidのWi-Fi設定でカメラへ接続している。画面を開いただけでは通信しない。一覧の形式は `VER_100` と6列のCSVで、DCIM配下の英数字を含む対応名のみ受け付ける。
- 上限: 一覧4 MiB/リクエスト、最大20,000エントリー・1,000ディレクトリ・DCIMから4階層、1ファイルおよび保存済み試験コピーの合計512 MiB。接続/読取タイムアウトは各5秒、一覧または転送操作は120秒を上限に読取ごとに中止を確認する。ブロック中は読取タイムアウトまで待つ場合がある。
- 事後条件: 一覧サイズと受信サイズが一致し、同期書き込みと読戻しSHA-256照合が成功したコピーだけを固有名で確定する。EXIF補正は行わず、受信したバイト列を保持する。SHA一致は受信・保存の一致であり、カメラ側の内容証明ではない。
- 失敗/中止: 未完了コピーを削除し、成功済みコピーは保持する。部分転送の続きから再開せず、選んだファイルを最初から再試行する。画面が非表示になると中止を要求する。プロセス終了で残った一時ファイルは容量計算に含め、試験用コピーの削除操作で除去できる。
- 保存: `files/ep7-wifi-poc` のアプリ専用領域。MediaStoreと通常の取り込み履歴へは登録せず、試験用コピーを削除してもカメラとライブラリの写真は変わらない。
- 計測: 一覧取得秒数、HTTP開始から受信完了までの秒数とバイト数/MiB/s、保存検証を含む操作全体の秒数を画面へ表示する。転送時間には受信中のファイル書き込みを含む。カメラ情報・画像一覧・オリジナル・SHAは外部の診断先やissueへ送信しない。

## 操作

1. カメラのWi-Fiを有効にし、AndroidのWi-Fi設定で接続する。
2. Loupeの［取り込み］→設定→［E-P7のWi-Fi転送を試す］を開く。
3. ［画像一覧を取得］を押す。一覧がない場合や失敗した場合は接続とカメラの状態を確認する。
4. 写真を選び、［選んだ1枚を試験転送］を押す。成功後のサイズ・速度・全体時間を確認する。
5. 試験が終わったら［試験用コピーを削除］で端末の試験コピーを片付ける。

UIはAppCompatActivity、MaterialButton、LinearProgressIndicator、標準Spinnerを使用する。本文と選択・操作は縦スクロール可能で、操作域は48dp以上。OSのsystem barsとdisplay cutoutを避け、結果はpolite live regionで通知する。通常状態・取得中・一覧・転送中・成功・失敗・中止を文字でも区別する。

## 検証

`sh tests/ep7-wifi.sh` は合成HTTPで再帰列挙、パス検証、サイズ変更・短縮応答・リダイレクト拒否、受信/保存SHA一致、中止・再試行と後始末を検査する。Android画面の合成検査は `ep7-wifi` instrumentation modeで行う。

2026-11-15、実E-P7と24129PN74Gで、525件の一覧、JPEG1件、同一ORFの成功2件、中止と再試行、試験コピーの削除を確認した。検査対象はソース `77864ad` の別applicationId `jp.nano.rawgallery.ep7poc`。測定値・条件・保全確認は [実機検証の記録](https://github.com/ktnyt/Loupe/issues/121#issuecomment-6894140552) を参照する。

大量連写・長時間転送、電波断やカメラ切断からの再接続、実TalkBack音声、常用本体への統合導入は未確認。受信と保存のSHA一致はカメラ側のハッシュとの照合を意味しない。

## 後続工程

共通履歴は、リーダーの識別とカメラ/オリジナルの識別を分け、ファイル名・サイズ・日時は重複候補の絞り込みに使う。同名別内容を排除しないよう、必要な内容照合と、既存のEXIF補正前後のハッシュを区別する。JPEG/RAWは個別ファイルとして管理し、撮影の関連付けを別に持つ。

SD差分取り込み、Wi-Fi/SDの共通履歴、接続時の自動開始、転送再試行の自動化、カード戻し忘れ通知は後続工程。既存USB経路の動作は変更していない。

## 通信仕様の根拠

Olympus発行の [OPC Communication Protocol 1.0 alpha](https://raw.githubusercontent.com/ccrome/olympus-omd-remote-control/master/OPC_Communication_Protocol_EN_1.0a/OPC_Communication_Protocol_EN_1.0a.pdf)、p.13（User-Agent）、p.66–67（一覧とFAT日時・属性）、p.117（オリジナルの直接GET）を参考にする。互換性の未確認を残し、他機種の実装をE-P7の保証として扱わない。
