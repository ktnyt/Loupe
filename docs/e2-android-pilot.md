# IDrive e2東京へのAndroid接続試行

[クラウド保管の設計](b2-archive-design.md)の保存先をIDrive e2東京に更新する。端末SQLiteを利用し、D1同期は後続。[issue #75](https://github.com/ktnyt/Loupe/issues/75)。

| 目的 | 要件・契約 |
| --- | --- |
| 原本の保管 | 指定したORFとJPEGを端末上で読み、サイズとSHA-256を確定する。非公開・バージョニング有効の試験バケットへ、東京の公式HTTPSエンドポイントを固定して送る。 |
| 原本の復元 | 送信前にSQLiteの保管記録を作る。指定版のGETで版・サイズ・SHA-256が一致した後に確定する。DBを開き直し、その記録から復元できることを確認する。 |
| 再試行 | 同じ写真IDの処理を直列化する。保留記録がある場合は同じキーを読み、照合してから確定する。明示的な404以外の失敗で再送しない。不一致では上書きしない。 |
| 認証情報と原本の保護 | キーは試行時に端末アプリ専用領域へ一時投入し、読み込み直後に消す。TLS・接続先を制限し、リダイレクトは追従しない。既存DBとは別名で開き、原本の削除と既存自動同期は呼ばない。 |
| 待ち時間の計測 | Androidの時計でPUT開始から成功応答まで、GET開始からダウンロード・ハッシュ照合完了までを各写真で測る。USBでの素材準備は計測に含めない。 |

原本転送、保管記録、版指定取得を専用の計測モードから動かす。通常画面の保存先切り替え、永続キー設定、プレビュー・カタログ、既存Amazon記録の移行、端末容量整理は後続段階。

合格条件はRAW/JPEGそれぞれの保存、SQLite再オープン、保存記録からの版指定復元、サイズ・SHA-256一致。転送件数、容量、秒数、接続条件、使用APKを記録し、資格情報と写真名は含めない。

同じ試行IDで再実行すると、同じ試験DBと写真IDを参照する。結果の受信が途切れた場合に備え、試験DBは完了後も保持する。再試行時は同じ写真を指定する。
