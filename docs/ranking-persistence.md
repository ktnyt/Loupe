# 順位保存の契約

対象は単写の1位指定と、連写の比較・同順位・取り消し・モード変更・1位指定。表示、順位フィルター、共有対象と写真の識別は、確定済みの同じ順位情報を参照する。

## 保存形式

既存の`rankings` preferencesとXML、`v1-`・`single-best-v1-`のキー生成を維持する。写真IDのソートとSHA-256、旧形式・`A:`・`B:`の履歴を変更しない。未登録、保存済みの空文字、明示的な`A:`・`B:`を区別する。初回の比較で表示用に補う`B:`は保存済みの値ではない。

単写は未登録・`0`を未指定、`1`を指定として読む。不正な型や履歴は対象の読取失敗とし、初期化や上書きで隠さない。無関係な行・設定・写真原本を変更しない。保存先の移行は行わない。

## 確定値の読取

`RankingStore`は保存領域ごとの所有者を共有する。通常のアプリケーションではapplication context、検査で渡すpreferencesではオブジェクトの同一性を使う。Activityを保存処理の所有者にしない。

初期読込は専用workerでpreferencesを取得し、値のコピーを準備する。`Snapshot`は`PENDING`・`FAILED`・`READY`を区別する。`snapshot()`は待機せず、`READY`の読取はwriterのロックや実行待ちを取得しない。読込失敗後の`retryLoad()`は読取だけを再試行する。

1回のフィルター、件数計算、共有対象の導出には、同じ`Snapshot`と写真・束・選択の世代を使う。結果は保存領域とrevisionの両方に結び付ける。可変な`PhotoRanking`を別の画面やキャッシュへ共有しない。共有の確認後に順位による対象が変わった場合、起動前に再確認を求め、別の写真へ黙って差し替えない。

写真のSAF表現とMediaStore表現の選択に順位が必要な場合、`PhotoIdentityIndex`はSQLite書込transactionを開始する前に`READY`を確保する。バッチ全体で同じsnapshotを使い、未確認の順位を未指定と解釈して識別子を確定しない。競合する表現がない処理は順位の初期読込を待つ必要がない。

## 保存と失敗

`submitSingleBest`・`submitBurst`は、画面から独立したworkerへ操作を渡す。単写は従来の真偽値の照合、連写は対象キーの保存文字列と未登録状態を照合する。別キーの変更だけでは競合にしない。比較・取り消し・モード変更・直接の1位指定も、表示の根拠になった値へ照合する。

保存する候補と次snapshotを先に準備し、同期`commit()`が成功してから公開する。変更がある成功時だけrevisionを1増やす。変更なし、競合、失敗、補償だけでは増やさない。画面は保存済みの結果だけを反映し、古い画面への通知が無効でも保存結果を破棄しない。

`commit()`が失敗または例外になった場合、候補を公開しない。変更したキーだけを元の文字列または未登録へ戻す。補償に失敗した場合、最後の確定snapshotは読めるが、同じ保存領域の次の書込は変更なしや別キーも含めて止める。明示的な次の操作で先に補償を再試行し、成功後にその操作の前提を照合する。失敗した元操作は自動で再実行しない。汚れたpreferencesのメモリを読んで確定snapshotを作り直さない。

画面終了で開始済みの保存や補償を割り込ませない。`load`・`save`など同期互換メソッドは背景処理向けで、画面の読取・保存には使わない。

プロセスが保存結果の通知前に終了した場合、再起動後は実際の永続値を読む。曖昧な失敗から補償完了までに強制終了された場合、必ず旧値へ戻る保証は追加しない。通知されていない新値が残る可能性と、利用者が保存成功を確認した状態を区別する。

## 画面と検証

読込中を未選択の星、順位なし、フィルター0件として表示しない。読込失敗からの再試行は読取だけを行う。保存中は確定済みの値と比較中の写真を維持し、同じ操作の二重入力を止める。失敗では先へ進まず、競合では最新を読み直して新しい入力を求める。Material 3の状態、48dp以上の操作領域、読み上げとフォーカスを維持する。

ホストでは旧形式、同じ所有者の複数ハンドル、独立した保存領域、読込中・失敗・再試行、保存中の読取、メモリ更新後の保存失敗、補償失敗と後続操作、revisionと通知を検査する。永続値の検査は共有snapshotを再読取するだけで代用しない。

Androidでは専用AVDと合成データを使い、保存を保留した間の旧確定値のフレーム、保存後の新しいフレーム、比較の入力から描画、識別子確定前の順位待ちとSQLite書込、旧版からの設定・履歴保持を確認する。順位件数と写真件数、実際のXML保存時間と検査用の待機、メモリ画像とコールド読込を分ける。frame commitはGPUへの提出であり、物理表示の完了時刻ではない。条件別の実測・失敗・未確認範囲は[Issue #249](https://github.com/ktnyt/Loupe/issues/249)へ記録する。
