# タグ解析の進捗表示

## 目的と範囲

「写真を解析」を押した利用者が、処理の継続・解析済み枚数/対象枚数・中止・完了を画面から判別できる。[タグConfidence](tag-confidence-contract.md)と[参照HTML](design/loupe-tag-analysis-progress.html)の解析中表示を回復する。

## 要件と契約

- 400ms以上続く解析では、最終のView階層に置いた進捗表示が可視になる。数値更新が続く間も表示を失わない。
- 解析済み/対象枚数は推定タグ数と区別する。32541枚の桁数を320/400dp・文字1.0/1.3で読めるようにし、必要な操作へスクロールで到達できる。
- 開始直後の短い処理を無理に点滅表示せず、既存の400msの遅延と状態記号の規約を保つ。完了・失敗・中止の既存契約を変えない。
- 解析対象、実行順、特徴、判定器、スコア、判断履歴、閾値、原本を変更しない。共通StatusViewや他画面へ修正を広げない。
- 進捗の開始は、下部パネルを含む画面構築が完了した後に行う。

## 検証と計測

生成写真・起動前に隔離したDBで解析workerを保持し、400msを超えて実際の表示を確認する。修正前に同じ検査が欠落を検出し、修正後に成功することを確かめる。通常の数値更新、長い数値、画面の再描画、中止/完了の回帰を確認する。

実機キャプチャと独立UI/UX評価で、可視性と判読性を確認する。表示開始から400ms後の状態と検査条件をissue #48へ記録する。利用者が開始した解析への割込み・アプリ更新は、その処理の完了まで行わない。検証は利用者の判断や写真を変更しない。

## 参照の採用範囲

Claudeの[補足HTML](design/loupe-tag-analysis-progress.html)は解析中の回る印と解析済み/対象枚数の可視性・桁数の参照とする。320dp・文字1.3倍のブラウザ表示を確認した。HTMLの状態行の位置、中止の遅延、完了/失敗の通知、パネル高さ62%は模擬であり、今回の変更要求に含めない。Androidの既存配置・48%上限・中止の即時操作・完了/失敗の契約を維持する。ブラウザの線形文字拡大とAndroidの非線形拡大の差は実機で照合する。
