# #128 SD取り込みの操作と待ち時間

対象は0.31.51（mainの0c5b44b）以降のSD取り込み。SDからmicroSDへの取り込みと登録待ちの処理は[カード交換の契約](sd-source-swap-contract.md)を引き継ぐ。

## SDの開始と設定

- 文脈。接続状況に応じた上部の開始ボタンと、SD専用欄の開始ボタンが、同じUSBリーダーで外部カードに保存するときに同じSD取り込みへ進む。設定が画面に展開されているため、開始と設定の所在が分かりにくい。
- 目的。普段は一つの開始ボタンでSDから取り込み、取り込み元やオプションを変更したいときに設定を開ける。
- 要件。SD欄に開始とペンの設定ボタンを置く。同じSD処理を呼ぶ取り込み状況欄の開始ボタンを、その構成では表示しない。通常のカメラUSB操作とWi-Fiの操作は引き続きそれぞれの入口で使える。ライブラリの長押しでSDから開始できる。
- 契約。設定を開くだけでは再登録・取り込み・自動取り込みの変更をしない。フォルダの選択と登録確認、選択取消、内容確認、自動取り込み、権限確認、進捗の中止と再試行を維持する。同じUSBリーダーで外部へ保存する確認では取り込み元と先、既存の写真形式の初期選択を示し、JPEGとRAWを選び直せる。原本は残る。
- 画面。既存のWi-Fi欄と同じペンの配置を使い、読み上げ名は「SDカード取り込み設定」とする。詳細はスクロール可能なMaterialの画面に収め、閉じる・戻るで取り込み画面へ戻れる。設定・取り込みが使用できない状態は、操作が重ならないよう以前の制約を維持する。320dp・文字1.3倍と通常幅で操作を確認する。

## 通常の再取り込み

- 文脈。実機の0.31.50は1,299枚の一覧を約2秒で取得し、その後327枚の既存写真の保存先を全量確認してから新規保存を始めた。0.31.51でも既存の証拠があれば写真を1件ずつAndroidへ照会し、証拠がなければ保存先を初回に読み直す。どちらも新規保存が既存写真の確認を待つ。
- 目的。通常のSD取り込みは新規・変更の候補をすぐ保存し、履歴がある写真の本文や保存先を読み直す時間をなくす。
- 契約。選択したSDフォルダの完全な一覧を一度取得する。更新日時の順や直近の数枚で絞らない。Android写真一覧だけに頼ると撮影直後の未登録写真を取りこぼすため、候補検出はSDフォルダを使う。原本を選ぶための読み取り許可、保存先、カードと接続世代の確認を分類前後に行う。
- 通常モードの履歴一致は、確認できたカードID、選択範囲内の相対パス、正の更新日時、サイズが既存のoriginal-byte-v1受領記録と一致する場合に限る。1回のローカル台帳照会を使い、履歴一致を写真の現在の保存状態だとは扱わない。古い受領記録のない写真、更新日時・サイズなどが変わった写真、識別できない写真には従来の照合を行う。
- 履歴一致した写真は、その回の確認対象から外す。原本MediaStore照会、保存先の状態照会・読み取り、ハッシュ計算を行わず、照合証拠の準備を要求しない。写真が別の場所へ移動・削除されていても、通常は取り込み済みという履歴を使う。保存先が存在するか確認し直すには「内容も確認する」を使う。厳密確認では従来どおり原本と保存先を比較し、保存先の消失が確定した場合の復旧を維持する。
- 新規・変更・不明、明示確認の原本経路、重複排除、原本を残す条件、公開・履歴の確定、安全な再試行は既存契約に従う。同じサイズと更新日時のまま内容が変わった写真は、メタデータによる通常判定の限界として、明示確認で検査する。履歴一致をバックアップ・削除・移動の許可には使わない。
- 検証。1,299件または4,800件規模の一覧に、変更なしの履歴、更新された同名写真、古い撮影日時の新規写真、Androidに未登録の写真を混ぜる。既存分について個別照会と本文読み取りが0であり、新規候補だけがコピーに進むことを検査する。明示確認は既存の全量読み取り経路を通る。元カードが変わった場合、登録待ち、途中の取消、完了時の件数を区別する。時刻差分のみの省略を使わない。
