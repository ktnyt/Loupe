# Issue #1 開発着手: 人の判断モデル

2026-10-25（日本時間）。Issue本文・コメント0件を確認。開発着手の依頼は以前の「設計のみ」を更新するが、方式案すべての採用を意味しない。

## 目的と範囲

T1の判断と訂正をT5で失わずに扱うため、方式・画面に依存しない判断履歴から着手した。既存の選抜・共有状態とは独立させる。手動版の処理場所・対象・操作は下記の追加契約で合意した。比較実験の場所・写真、外部送信、性能予算、自動付与条件は未決定。

## 実装前の契約（委譲範囲で具体化）

- 入力は不変のタグID・写真論理ID・操作ID、期待する判断版、判断値。IDの生成と実在確認は将来の呼び出し側の責務で、URIや索引位置を推測でIDにしない。
- 人の判断値は付与・明示的除外・未判断。自動付与を入力する経路を設けない。
- 判断履歴は不変。更新は新しい履歴を返す。同じ操作IDと同じ内容の再送は履歴を増やさず、同じIDで異なる内容は拒否する。
- 判断版はタグ・写真の組ごとに増加。期待版の不一致は拒否し、別タグや別写真の変更は競合しない。
- 訂正は新しい判断として追記する。undoは直近の対象操作と一致する場合に限り、直前の判断へ戻す訂正を追記する。初回付与を戻すと未判断になる。
- このモデルは保存済み状態ではない。将来のストアは現在値・履歴・再評価要求を同じトランザクションで保存し、成功後にのみUIへ公開する。本実装単独で保存成功を保証しない。

## 手動版の追加契約（実装前）

ユーザー回答で、Androidの手動版・左パス／右付与／別操作で除外、端末内写真を対象にRAW・JPEG・コピーを別写真として扱うことを確認した。移動先へ自動で引き継がず、孤立した判断は保持する。

- 写真対応はURIとサイズ・更新日時・追加日時・作成日時の組にUUIDを対応付ける。索引のordinalやbundleを使わない。同じURIでもメタデータが変われば新しい対応となる。バイト内容の一致を保証する方式ではなく、同じURI・全メタデータを保った置換は検出できない（初期版の制限）。名前による移動先推測・クラウドとの統合はしない。
- タグ名は前後空白を除き1〜80文字、同名は既存タグを選ぶ。タグIDはUUID。初期版は名前変更・意味変更・自動付与を提供しない。
- `tags.db`をGalleryIndexから分離し、判断履歴・現在値・再評価要求を一つのSQLiteトランザクションで更新。保存失敗では次写真に進まない。再評価要求は将来用に保存するがモデルを実行しない。
- 専用タグ画面で現在のアルバム・カメラ範囲の端末写真を手動確認する。類似検索とは表示しない。通常の写真閲覧のスワイプは変更しない。
- 左パスはDBの判断を変えず、現在の確認セッション内で再提示しない。セッション終了後に再開可能。パスのundoはその写真に戻り、判断のundoは訂正を保存してから戻る。
- 付与済み一覧は同じ範囲内のアクセス可能な写真だけを表示する。参照が見つからない判断は削除しない。
- 画像取得・DBアクセスはバックグラウンドで行い、古い画面の読み込み結果は破棄する。中断後も確定済み判断は再読込できる。

- 実装: `TagJudgments.java`（不変の履歴・版・再送・undo）、`TagStore.java`（SQLite永続化）、`TagActivity.java`（手動操作・タグ別閲覧）。写真一覧・詳細の「タグ」から接続。

- `git diff --check` 成功。
- `assembleDebug assembleDebugAndroidTest lintDebug` 成功。lintは0エラー・27警告。既存の保存・共有準備テストも成功。
- 承認後に接続端末へデータ保持で更新。テストAPKの初回導入は端末側で取り消され、再試行の承認後に導入成功。
- 実機の`TagStoreChecks`成功。一時DB・架空参照で、URI変更・サイズ変更の分離、操作の重複防止、再評価更新時の障害注入による履歴・現在値のロールバック、DB再接続後の復元、undoと再送、再評価版を確認。実写真は変更していない。
