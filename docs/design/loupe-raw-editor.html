Loupe — 実験的な内蔵のRAW現像の画面（Issue #53）

左は元のアートボード S08「08 写真詳細」、右は loupe-photo-edit-toolbar.html の写真の画面と、そこから開く新しい「現像（実験）」の画面です。［編集］を長押し（0.5秒）するか、［情報］の中の［現像（実験）］で開きます。［編集］の通常のタップは既存の外部編集のままです。面の上でドラッグすると両方の軸、右と下の辺では片方の軸だけが変わります。

原本は上書きせず、長辺2048px以下のプレビューから別のJPEGとして保存する実験版の案です。写真は合成の色面と図形、画素数などの値は合成です。Androidにはまだ反映していません。

1. 入口（写真の画面は既存のまま）

  • 写真の画面（S08 の黒い背景・上の日時・切り取らない表示・下の dock）と ［編集］の位置・通常のタップ（既存の外部編集＝ACTION_EDIT の選択画面）は変えない。
  • ［編集］を長押し（0.5秒）すると「現像（実験）」を開く。読み上げ名「編集。端末の写真編集アプリで開きます。長押しで現像（実験）」。
  • 長押しを知らなくても届くように、［情報］のシートに行［現像（実験）］（48dp・アイコン22dp）を足す。dock の操作の数は増やさない。

4. 2DUI（正方形の面＋右の縦軸＋下の横軸）

項目値
配置上に「横 {軸名} {値}　縦 {軸名} {値}」（13sp・値600・等幅の数字）。その下に、正方形の面（一辺 S）と右に縦軸（幅48dp・高さ S）、面の下に横軸（幅 S・高さ48dp）。面と軸の間は8dp。3つの操作域は重ならない
一辺 SS = max(120, min(画面の幅 − 32 − 56, (高さ − 56 − 84) × 0.36))。320dp・844dp で232dp、400dp・844dp で253dp、640dp で180dp
面#141416・角丸8dp・内側の線1dp #2E2E32。基準線（初期値の位置）1dp #3A3A3F。端に短い名前（12sp・#A9A9A4）。点 24dp の #EDEDEA（黒い2dpの縁）。ドラッグで両方の軸が変わる
辺のスライダー線4dp #3A3A3F、初期値の目印2dp #6B6B70、つまみ20dp #EDEDEA。縦軸は縦の値だけ、横軸は横の値だけを変える。面の点と両方のつまみは同じ値で連動する
読み上げとキー面は「{横}と{縦}の面。左右で{横}、上下で{縦}」・値の文「色温度 プラス12、色かぶり マイナス4」。矢印の左右で横、上下で縦（Shift で10倍）。辺は「{名前}（縦だけ）」「{名前}（横だけ）」の role=slider
範囲多くは −100〜+100（1刻み）、露出は −5〜+5EV（0.05刻み）、トーンの入力 5〜95・出力 0〜100。表示は「+12」「−4」「±0」

5. 状態と境界

状態表示と動き
読み込み中長辺2048px以下のプレビューを読み込む。400msまでは何も出さず、そのあと回る印と［中止］。調整・保存・比較・初期化は無効。中止・Back で写真の画面へ戻り、現像は開かない
未対応のRAW三角の印と「未対応のRAW」。カメラのJPEGには黙って置き換えない。読み上げで、端末の Back で戻れることを伝える
読み込みの失敗三角の印と［再試行］
反映待ち操作中はプレビューを近似ですぐ更新し、本処理が400msを超えるときだけ右上の印。値の変更は待たずに続けられる（新しい値で処理し直す）
保存の前シート「JPEGで保存」に「2048 × 1536 px　JPEG　実験版・別のファイル」。フル解像度と誤解させない。［保存］［キャンセル］。彩度MAXはここでオフにし、保存に残さない
保存中［保存］に回る印、調整・比較・初期化は無効、Back は止める
保存の失敗［保存］の右上に三角の印。調整はそのまま、もう一度押すと再試行
保存の成功40dp の完了の合図を900ms。別のJPEGとして保存し、原本は変えない。そのあとは Back で確認なしに戻る
Backシート → 閉じる。未保存の変更がある → 「変更を破棄しますか？」［破棄］［編集を続ける］。保存済み・変更なし → そのまま写真の画面へ（［編集］にフォーカス）
Undoこの初版には入れない（［初期化］はタブ単位）。後で入れるときは、1回のドラッグ（押してから離すまで）を1手とし、彩度MAX・比較・拡大は Undo の対象にしない

6. 確認の観点と注記

  • 縦画面だけ。320・390・400dp × 文字1.0・1.3倍 × 高さ640・844dp、全5タブと3つのサブタブで、省略・はみ出しがなく、押せるものは48dp以上、面と辺の3つの操作域が重ならず、上の操作と下のタブが常に見え、写真の領域が最低の高さを保つことを右の検査で確かめています。
  • プレビューの見た目は CSS で近似した合成です（実際の現像の処理ではありません）。2048 × 1536 px などの値も合成です。写真の原本・個人情報・URI は使っていません。
  • 未検査：実機のRAWの読み込みと処理の速さ、対応するRAWの種類、JPEGの保存先と画質、ピンチの細かい手触り、TalkBack での読み上げの順、非線形の文字の拡大（Android 14以降）。
  • 元のアーティファクトとこれまでのHTMLは変更していません。Androidにはまだ反映していません（Issue #53 の実験版の案）。
