1. 契約と範囲

  • #13の契約：「その他」メニューが、初回も再表示も、最初の描画から現行の寸法・位置で表示され、表示中に位置・幅・高さが変わらないこと。直すのは位置のちらつきだけ。
  • 対象：アルバム一覧・写真一覧・タグなど、「その他」メニューを開くすべての画面。
  • 範囲外（変えない）：寸法・色・角丸、項目と並び、ラベルの文言、読み上げの挙動、キーボードの扱い（ADJUST_RESIZE）。写真の原本・順位・タグ・選択の状態。説明文や演出の追加。
  • #8へ分けるもの：全幅にする、角丸28dpにする、高さの上限をほぼ全画面にする。今回は採用しない。

2. 現行の寸法（維持する値）

3. 受け入れ条件

  • 最初の1フレームで、幅・左右の位置（中央）・下端からの距離・高さが最終値と同じ（±1px）。中央や横など、別の位置に描かれるフレームがない。
  • 表示が落ち着いたあとから閉じるまで、メニューの位置・大きさが変わらない。中身のスクロールは除く。キーボードの開閉によるresizeも除く（4. を参照）。
  • 確認方法：画面録画（60fps以上）をコマ送りして、最初のフレームと落ち着いたあとのフレームを比べる。参照HTMLの記録と同じ観点で見る。

4. 場面ごとの条件

場面条件
初回表示アプリの起動直後や、その画面で初めて開くときも、受け入れ条件を満たす。gravity・幅・高さの上限は、最初に描かれる前に確定させる
再表示閉じたあと何度開いても、初回と同じ。表示後に配置を直さない
戻る（端末の戻る）今の挙動のまま（メニューを閉じる）。閉じる途中で位置が横や中央へずれない
外側タップ今の挙動のまま。閉じる途中で位置がずれない
項目の選択今の挙動のまま。閉じて項目の画面へ移る途中で、メニューが別の位置に描かれない
文字拡大拡大後の中身の高さで最初から描く。見えている高さの48%を超えたら、上限の高さで最初から描き、中をスクロール。拡大前の高さで出してから伸ばさない
読み上げ（TalkBack）挙動は変えない。メニューが別の位置に一瞬描かれないので、読み上げのフォーカス枠が最初の位置から動かないことだけを確認する
キーボード（その他メニュー）ADJUST_RESIZEのまま（画面と下部の操作バーはキーボードの上に縮む）。キーボードを閉じる・待つ処理は追加しない。キーボードが出ているときに開いたら、resize後の見えている範囲の下部中央に、最初の描画から表示する。高さの上限48%も、その見えている高さが基準
キーボードの開閉（表示中）表示中にキーボードが開閉したときの移動はresizeによるもので、今の挙動を維持する。ちらつきとは扱わない
入力のあるSheet（例：新しいタグ）IMEが出たときの既存のresizeを維持する。#13ではこの動きを変えない。ただし、開くときの最初の描画は同じく最終の位置で出ること

5. Android 実装への注意（原因は調査中）

  • 今の共通Sheetは show() のあとで gravity・幅・高さを設定している。Dialogの初期値（中央寄せ・中身の幅）で1フレーム以上描かれてから配置が変わると、報告の症状と一致する。
  • 直し方は決めない。条件は「最初に描かれる前に、現行の寸法・位置が確定していること」と「表示後に配置を直さないこと」。
  • 確認したい点：show前にウインドウの属性を設定できるか、テーマやスタイルで下部中央・幅・上限を指定できるか、48%の基準を最初の描画の時点で取れるか（resize後の高さを含む）、初回だけ中身の測定が遅れていないか。

6. 参照HTMLの使い方

  • 「初回として開く」：初めて開いた状態として開く。「もう一度開く」：閉じてから開き直す。
  • 「スロー」：今の動きの再現を10倍に遅くする。
  • 記録：開いてから落ち着くまで、フレームごとにメニューの左・上・幅・高さを記録し、最終値と同じかを表示する。最終値が現行の寸法（幅・中央・下端からの距離）と合っているかも判定する。
  • 「キーボード表示中に開く」：キーボードを出したまま開く。「キーボードを閉じる（resize）」で、閉じたあとのresizeの動きを確かめられる（この移動はちらつきとは扱わない）。
  • 閉じる方法：暗幕のタップ、「閉じる」、「戻る（端末の戻る）」、Esc。項目を押すと、ダミーの項目画面に移る。
  • 左の「今の動き」は症状を再現したもので、実機の描画そのものではない。項目とラベルはデザインのダミーで、現行アプリの文言とは限らない。
