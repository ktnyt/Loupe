Loupe — 現像（実験）：原寸の処理と保存（Issue #55）

左は元のアートボード S08「08 写真詳細」、右は loupe-raw-editor-overlay.html と同じ配置（7つのタブ・写真いっぱい・カーソルだけの2DUI・補助の行）のまま、原寸の処理に関わる状態・ヘルプ・保存の確認だけを変えた版です。軽いプレビューを先に出し、原寸の linear cache を背景で準備します（約3秒の模擬）。準備中も編集できます。

原本は変えず、端末の中に別のJPEG（原寸・合成の例 6000 × 4000）として保存します。2048 への置き換えはしません。写真は合成の色面と図形、寸法も合成です。Androidにはまだ反映していません。

1. 変えたことと保つこと

  • 変えないもの（loupe-raw-editor-overlay.html のまま）：7つのタブ（WB・質感・トーン・明るさ・明暗・白黒・カラー）、写真いっぱいの表示（全体を表示し、拡大したときだけ切る）、写真の上に見えるのはカーソルだけの2DUI（7タブで同じ位置・寸法）、補助の行（彩度MAX・かすみ・コントラスト・モノクロ・［拡大］）、上の行（ヘルプ・比較・初期化・保存）、彩度MAX は表示だけ、モノクロの色相260・彩度11・輝度+2、2本目の指で値を戻してピンチへ移る動き、辺の片軸の操作、トーンの1点のカーブ、補正前の比較、今のタブだけの初期化、未対応のRAW・読み込みの失敗、未保存の破棄の確認、［編集］の通常のタップ＝内蔵の現像・長押しと［情報］＝外部のアプリ。
  • 新しいボタンは足さない。原寸に関わる表示は、既存の #17 の札（右上の格子＋回る印／格子＋三角）、［保存］の回る印と失敗の印、ヘルプの行、保存の確認の文だけで出す。

2. 原寸の流れ

状態表示動き
preview長辺2048pxの軽いプレビューを先に表示すぐに編集できる。続けて原寸の準備を背景で始める
fullprepare（準備中）400msを超えたら右上に札（28dp・格子＋回る印・rgba(0,0,0,.62)）。反映の印はその左（右から64dp）原寸の linear cache を背景で準備。操作を優先し、準備中も2DUI・補助の行・タブ・保存の操作はすべて使える。読み上げ「精細な表示を準備しています。編集はそのまま続けられます」
provisional（仮の表示）準備中・detail の作り直し中は、プレビューを拡大した仮の表示（少しぼける）拡大の上限は準備中でも原寸の 1:1。仮の表示はあとで精細な表示に置き換える
ready（完了）札を消す。精細な画像に置き換える置き換えのとき、表示の位置（拡大・移動）と編集の値は変えない
detail原寸の detail は今の表示範囲（viewport）だけを作る拡大・移動・値の変更が終わってから作り直す（約0.3秒の模擬）。作り直しの依頼ごとに番号を付け、古い番号の結果（古い snapshot）は表示しないで捨てる
detaildrag（拡大中の操作）操作中は仮の表示2本の指の移動・拡大、1本の指の2D・補助の行のスライダーのあいだは detail を止める。指を離すと今の範囲だけ作り直す
fail（失敗）右上の札が格子＋三角（線1.5dp #FF8A7A、押せる領域48dp）低い解像度のまま閲覧・編集を続ける。拡大の上限はプレビューの 1:1。札を押すか［保存］を押すと再試行。読み上げ「原寸を準備できませんでした。低い解像度で表示と編集を続けられます。拡大はプレビューの等倍まで、保存は原寸の準備のあとです。押すと再試行」
retry（再試行）札が準備中の形に戻る原寸の準備を最初からやり直す

3. 拡大の上限

  • 上限 = 写真の元の寸法の長辺 ÷（全体表示の写真の幅 dp × 端末の密度）。固定の4倍にはしない。合成の例：6000px ÷（400dp × 2.625）= 約5.71倍（400×844・400×640 とも全体表示の幅は400dp）。
  • 原寸の準備に失敗したときは、プレビューの 1:1：2048px ÷ 1050px = 約1.95倍。上限を超えていた拡大はそこまで戻す。
  • ［拡大］は 2.5倍（上限がそれより小さいときは上限）と全体の切り替え。ピンチとホイールは 1倍〜上限。

4. 保存

状態表示動き
原寸ができている保存の確認「JPEGで保存」に「6000 × 4000 px　JPEG　実験版・別のファイル」（モノクロのときは「モノクロ」も）［保存］で原寸の JPEG を端末の中に別のファイルとして保存。原本は変えない。彩度MAX と比較は保存の前にオフ
savewait（原寸の準備中に［保存］）［保存］の中に回る印（地 #2A2A2E・文字 #C9C9C4）。読み上げ「原寸の準備を待っています。押すと中止」準備ができたら保存の確認へ。もう一度押すと待ちを中止（準備は背景で続ける）。待っているあいだも編集できる（保存は最新の値）。2048 には置き換えない
原寸の準備の失敗［保存］の右上に三角の印［保存］を押すと原寸の準備を再試行し、待ちに入る
保存中・保存の失敗・成功既存のまま（回る印／三角の印／40dp の完了の合図）失敗は調整をそのままにして再試行
back（待ち・保存中の Back／バックグラウンド）［保存］が元の形に戻る保存を取り消す（ファイルは作らない）。編集の画面に残り、もう一度 Back で未保存の確認

部品値
写真の領域400×648dp（844）／400×444dp（640）。上の行56dp・補助の行56dp・下のタブ64＋20dp は前回のまま
2DUI面 328×328dp、縦の帯 48×328dp、横の帯 328×48dp、間8dp。写真の領域の中の面の位置 (8, 132)／(8, 30)。7タブで同じ

反映の印原寸の札があるときは右から64dp、ないときは12dp（28dp の丸）
［保存］最小48×64dp・角丸24dp。通常 #EDEDEA／#111111、待ち #2A2A2E／#C9C9C4 と回る印16dp、保存中は無効
ヘルプ既存の使い方に2行を足す（「精細な表示と保存は原寸の準備のあと。準備中も編集できます」「右上の格子に三角の印は原寸の準備の失敗。押すと再試行」）。今の値の表に「原寸 6000 × 4000：準備中／完了／失敗」と「拡大の上限」

6. 確認したことと未確認の範囲

  • 400×844・400×640（ほかに320・390dp）× 文字1.0・1.3倍で、7つのタブと fullprepare・provisional・ready・detaildrag・savewait・fail・retry・back の各状態を上の切り替えで確かめられます。右の検査で、写真の上の2DUIがカーソルだけであること、2DUIの座標がタブで変わらないこと、拡大の上限、押せるものが48dp以上であることを確かめています。
  • 準備中の編集、2本目の指で値を戻すこと、準備の完了で拡大の位置と値が変わらないこと、古い detail を捨てること、保存の待ちの中止と準備の完了で保存の確認に進むこと、失敗のときに2048 で保存しないこと、待ち・保存中の Back とバックグラウンドで取り消すことを、操作で確かめています。
  • 未確認：実機の原寸の linear cache の準備の時間・メモリ・端末の温度、実際の密度による拡大の上限、detail の作り直しの速さと表示のつながり、原寸の JPEG の画質と容量、保存先、バックグラウンドへ移ったときの Android の処理の止め方、TalkBack の読み上げの順、非線形の文字の拡大。
  • このHTMLの「精細」と「仮の表示」は、細かい模様のぼかしで近似した合成です。元のアートボードとこれまでのHTMLは変えていません。Androidにはまだ反映していません（Issue #55）。
