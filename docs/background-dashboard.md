# 処理状況ダッシュボードの契約

Issue #16の設計をもとに、#39で独立した`DashboardActivity`として実装する読取専用画面の契約である。画面・寸法は[Claude参照HTML](design/loupe-issue16-dashboard.html)の現在取得可能モードを基準とする。#17の非テキスト状態部品を継承するが、#17の状態部品を使用する。

## 目的と機能

「その他」から、写真閲覧の準備とタグ処理について現在分かっている状況を確認できるようにする。通常の写真一覧に常駐させず、一覧から詳細を開き、Android標準Backで同じ一覧位置へ戻る。表示のために処理を開始したり原本を走査したりしない。

対象は仮画像（ThumbHash）、プレビュー、タグ解析、自動タグ付与の4項目。同期や削除設定、タグ推論の変更（#1）は含めない。状態取得の有無と処理結果を区別し、未計測を0件・完了・100%にしない。

## 現在の取得元と限界

| 項目 | 取得元 | 意味・利用条件 |
| --- | --- | --- |
| プレビュー・仮画像共通の準備ジョブ状態 | `PreviewPreparationJob.snapshot` / `JobState` | 両工程を含むジョブの結果と時刻。プレビュー単独の成功/失敗に割り当てない。保存RUNNINGで実行主体がなければUNKNOWN。旧データもUNKNOWN |
| プレビュー対象数 | `preview-preparation`のtotal | 直近の索引から列挙したローカル写真数。全ストレージの現在総数とは限らない |
| プレビュー準備済み | 同ready | 開始時の`PhotoRepository.prepared`によるファイル対の存在確認と、その後のprepare成功加算。デコード検証済み件数やThumbHash完了数ではない |
| 準備の失敗数 | 同failed | その試行のプレビュー・ThumbHash生成例外。readyと重なることがあるため、残りをtotal-ready-failedで計算しない |
| 件数の信頼性 | `JobState.countsKnown` | 列挙完了と保存キー・値域を検証した場合のみ利用。未計測は—。既知の実測0は0と表示 |
| 最終観測時刻 | `JobState.updatedAt` | 状態保存の実時刻。取得時刻・推定完了時刻に置き換えない。0は— |
| 前面による実行抑制条件 | `PreviewPreparationJob.browsing()` | Activity started数>0という条件。停止完了の観測ではなく、ワーカーは次の協調チェックまで動き得る。COMPLETE等の保存状態をPAUSEDに上書きしない |
| 容量不足・OS待機等の理由 | 型付きの保存元なし | 旧表示文の部分一致で原因を推定しない。PAUSEDだけで容量不足と断定しない。理由を表示するには別途明示コードが必要 |
| 仮画像の件数 | `PreviewPlaceholders`には写真単位の有無のみ | ダッシュボード向け保存集計なし。表示時の全写真走査で補わず、現在はUNKNOWN / — |
| タグ解析 | `TagActivity`内のanalyzed / photos / analysisFailures等 | Activityのセッション内状態。永続する全体ジョブ集計ではなく、別画面から現在値として使わない |
| 自動タグ付与 | `TagActivity`内のautomaticCount / autoRunning等 | 同上。手動判断と自動付与を混同しない。ダッシュボードでは現在UNKNOWN / — |

`JobState`の数値と時刻は前回観測値であり、ライブラリ変更後も現在の完全な棚卸し結果を保証しない。保存RUNNINGから実行主体消失によりUNKNOWNに変わった場合は、有効な前回値と時刻を保持する。旧データ・未知kindはcountsKnown=false・updatedAt=0なので件数と時刻は—とする。snapshot.RUNNINGは取得時にactive>0だった観測であり、取得後の継続までは保証しない。

共通準備ジョブの結果は4工程とは別の補助情報として帰属を明示し、プレビュー・仮画像それぞれの処理結果として複製しない。独立した状態がない工程はUNKNOWNとする。前面の実行抑制条件は保存された観測結果と別に扱い、完了→停止のような架空の遷移を作らない。

## 表示と更新の契約

- 不変条件: 読取専用。原本・タグ・進捗・キューを変更せず、再試行・一時停止・再開・削除・再解析の操作を新設しない。
- 事前条件: 保存された状態を取得し、既知と未知、観測値と現在の実行主体、処理失敗と取得失敗を区別できること。型がない停止理由は未知として扱う。
- 事後条件: 詳細を閉じても処理状態は変わらず、一覧の位置と選択した項目を保持する。終了はAndroid標準Backで呼出元へ戻る。
- 状態取得はUIスレッドで写真・キャッシュを走査しない。既存の小さい保存済みスナップショットだけを読む。更新は画面表示開始時と前面中の間隔更新に限定し、停止時には解除する。更新間隔は5秒とし、表示開始・再表示時にも読む。
- 表示は#17の形・数値・単位を使用する。機能名・数値欄の見出し・時刻・必要な固定説明は残し、状態を示す長文を可視表示へ戻さない。完全な状態・対象範囲・原因・前回値の説明はAXへ残す。
- 取得に失敗した場合は前回の観測値と時刻を維持し、取得失敗の印を付ける。処理自体をFAILEDに書き換えない。初回取得失敗は—とし、架空の前回値を出さない。
- 既知の0件、未知、完了、一部失敗をそれぞれ表現する。readyとfailedが重なるため、単純な100%や残件の円グラフは作らない。
- 通常の読み上げはユーザーが項目へ移動した際に行い、間隔更新ごとの数値読み上げで操作を遮らない。意味のある状態変化だけをpolite通知する。

## 検証と取得範囲

設計検証は合成データで「その他→一覧→各詳細→標準Back」、320/400dp、文字1/1.3倍、未知・既知0・進行・停止・一部失敗・完了・取得失敗を確認する。将来の計測済み例と現在実装可能な例を分ける。HTML検証をAndroid動作確認の代わりにしない。

[実装 #39](https://github.com/ktnyt/Loupe/issues/39)は、4項目と共通ジョブの保存観測値を表示する。`DashboardObservation`は値・時刻・取得失敗を保持し、`DashboardActivity`はバックグラウンドで初回と5秒ごとに取得する。onPauseで更新を解除し、進行中の古い取得結果を適用しない。表示値の更新ではViewを維持する。詳細からBackすると一覧の位置と起点カードのフォーカスを復元する。停止理由の型付き観測と工程ごとの集計は未実装。現在の集計不足を埋めるためにタグ推論や背景処理の実行条件を変更しない。追加の状態保存責務の分離が必要なら、開発フローに従い先行リファクタリングissueを作る。

Android実装の完了には、原本走査を増やさないこと、前面/背景/再作成、戻る位置、更新解除、取得失敗、TalkBack、文字拡大、実機と参照HTMLの独立比較を確認する。

## 採用する画面仕様と検証範囲

「処理の状況」の一覧は左右16dp、カード間8dp、カード内上下12dp/左右14dp、角丸14dp、最低72dp。機能名15sp、数値14sp、欄名12sp。共通準備ジョブと前面抑制条件は点線の補助行で分離する。詳細の数値行は最低56dp。前回値には16dpを基準に文字倍率へ追随する時計+戻り矢印の履歴印を数値・時刻・バーへ添え、色だけに依存しない。詳細に固定の凡例を置きAXにも前回の観測値/時刻を明記する。内容は文字拡大に合わせて伸長しスクロールできる。アプリ内Backボタンは置かない。

合成例でその他→一覧→4詳細→標準Back、320/400dp・文字1/1.3倍の12状態（計48条件）の一覧に横はみ出し・48dp未満操作がないことを確認した。480dp高の一覧から詳細へ移り、Backで同じスクロール位置へ戻った。未知・既知0・実行主体消失・列挙前失敗・初回/前回値あり取得失敗の表示とAX説明を取得元と照合した。

取得後にHTMLのAX文と仕様表を調整し、RUNNINGの生存確認時点と保存時刻の帰属を分離、件数不明から失敗タイミングを推測しない形にした。HTMLは設計の検証であり、Androidの描画・実処理・TalkBack音声は未検証。設計レビューの経過は#16に記録する。
