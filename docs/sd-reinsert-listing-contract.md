# SDを挿し直した直後の一覧確認

- 文脈。SDのボリュームがマウント済みでも、その直後にAndroidから取得したDCIMの一覧が0件になる場合がある。実機では以前の写真の場所を直接指定できる一方、フォルダを列挙できず、取り込みが0件で終了した。取り込み元だけを再マウントした後、1,299枚の既存写真とJPEG 108枚を確認した。Androidの写真登録はさらに後で完了した。
- 目的。差し替え直後に空に見えるカードをすぐに写真なしと扱わず、安全な範囲で自動取り込みを続ける。
- 契約。マウント済みの外部SDを読み取る既存経路で、完全な一覧が写真・動画とも0件、または読み込み中の場合だけ、短く待って同じ接続で1回確認し直す。既存の一覧取得の時間上限、キャンセル、読み取り許可、選んだフォルダ、取り込み元と保存先、取り外し世代の確認を維持する。正常に候補がある回は一覧を追加で問い合わせない。
- 2度目も完全な空の場合、同じボリューム・選択範囲にある少数のMediaStore登録を候補にする。既存の読み取り許可を使って、該当する1枚の文書の存在を、完全な単一行の照会で直接確認できた場合だけ、一覧に矛盾があると判断する。登録だけ、別カード、別フォルダ、曖昧な照会は証拠にしない。矛盾した一覧から取り込みを始めず、件数を確定せず、元カードの再接続を案内する。
- 本当に空のフォルダ、動画だけ、形式の絞り込みで0件、候補の写真にAndroidへの登録待ちがある場合は、従来どおり区別する。個別の写真がAndroidに未登録の場合も、フォルダ全体が空として表示しない。
- 一覧の再確認では原本と履歴を変更せず、Androidへのファイル登録やストレージ操作を行わない。再確認してもAndroidが新しいファイルを一覧に出さない場合は、取り込み元を再接続するか、下記の再マウントを使う。
- 検証。空→正常、読み込み中→正常、実在する写真を取りこぼした空、本当に空、古い索引、別フォルダ、切断・許可失効・中止・保存先変更を区別する。前回確認した1,407件の通常動作と新規準備時の登録待ちを壊さない。

## Shizukuで取り込み元だけを再マウントする

- 目的。USBカードリーダーのSDを差し替えてもAndroidが以前のボリュームを返すとき、下流の取り込みを始める前に取り込み元の接続を読み直す。
- 機能。SDカード取り込み設定で有効にすると、利用者が取り込み画面を開いたときに1回試す。初期値はオフ。AndroidのADB権限で動作中のShizukuと、利用者がLoupeに付与したShizukuの許可が必要。権限の要求は設定操作から行う。
- 事前条件。外部の保存先が明示され、別のマウント済みの外部カードが登録済みの取り込み元であり、USBカードリーダーを識別できる場合だけ試す。両カードは操作直前にも一意に一致し、取り込みと移動が共有するゲートを取得できること。
- 不変条件。登録済みの取り込み元に対応するスロットだけを取り外して再マウントする。保存先のmicroSD、写真、取り込み履歴はこの操作の対象外。許可のない起動、曖昧な候補、画面の復帰や回転、USB自動起動、進捗通知からは再マウントしない。
- 事後条件。取り込み元のマウントを見直し、取り込み画面に最新状態を表示する。別のカードは通常のフォルダ選択・許可を経て取り込む。実行中のマウント通知では自動取り込みを起動しない。失敗時は理由か再接続の案内を表示する。
