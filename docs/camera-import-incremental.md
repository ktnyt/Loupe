# カメラ写真の再接続と履歴確認

## 目的と契約

接続元の一覧、履歴で確認できた写真、内容の確認が必要な写真、新しく保存した写真を分ける。内容確認の対象数は新規保存予定数ではない。経路間の同一性は共通履歴の原本 SHA-256 と保存後検証で確認する。

USB マスストレージの exFAT、Wi-Fi 一覧、SAF には、この実装が安全に使える差分一覧 API がないため、再接続時もディレクトリのメタデータを全件列挙する。列挙と原本・保存先の内容読取りは別の工程である。時刻順による早期打切りや永続的な一覧キャッシュは使わない。

## USB マスストレージの既存写真

同じカメラの model/serial と、file_name/file_size/shot_at が一致した旧履歴を読み取り専用で分類する。旧履歴が示す実際の MediaStore URI が一意で、今回取得した保存先メタデータで公開済み・ゴミ箱外・期待するサイズと確認できた写真は、原本と保存先の内容読取りを省く。保存先画像は全体を一括照会し、写真ごとの MediaStore 照会はしない。同じ URI の重複履歴はまとめる。

`existing` は実際の URI ではない。有効な実際の URI の履歴が同じキーにある場合のみ、この補助記録を無視できる。実際の URI が複数ある、カメラからの削除記録がある、URI が不正、保存先がない・未公開・ゴミ箱内・サイズ不一致の場合は内容確認へ進む。照会が null、権限不足、照会失敗の場合は「不明」とし、存在しないと決めつけない。

同じ原本情報の共通 receipt があり、その保存先 URI も旧履歴と一致する場合、期待サイズには共通履歴の stored_bytes を使う。EXIF 修復による原本サイズと保存後サイズの差を再取り込み理由にしない。

この省略はメタデータと現在の保存先の存在を信頼する運用であり、原本や保存先の暗号学的な不変性を証明しない。同名・同サイズ・同時刻の原本への置換や、同じ URI・サイズでの保存先内容の置換は検出できない。`sd_verify_all` を選んだ回は設定を一度読み、旧履歴による省略を行わず、従来の原本 SHA-256 と保存先検証へ進む。

旧履歴による省略だけでは、共通 contents/receipts や SHA-256 を作らず、旧履歴の recordImport も追加しない。未確認・変更・消失・曖昧な写真には従来の内容確認、重複排除、回復処理を適用する。Wi-Fi/SAF の初回接続を USB の旧履歴だけで省略せず、その経路の receipt がなければ原本を取得して内容を確認する。

## 保存先

MediaStore のルートは従来の CameraSync を保つ。Wi-Fi/SAF の新しい写真は、取り込み履歴を持つ旧カメラの保存先 folder が一意に存在する場合、その folder を既定として再利用する。既存の USB Storage 設定が一つなら、Pictures/CameraSync/USB Storage と RAW 用の USB Storage-RAW を使う。

直近の接続方式を示す mass_storage flag には依存しない。この既定は importer の作成時に一度解決する。明示的な folderHint を優先し、候補がない・複数ある場合は従来の EXIF model に従う。既存写真の移動・改名や、カメラ設定の変更はしない。

## 計測と表示

一覧、履歴確認、内容確認、保存、完了・取消・失敗を共通の ImportProgress に反映する。候補数、履歴確認済み、旧履歴で確認済み、内容処理済み、追加保存、内容一致を区別し、不明の件数や時間は -1 とする。原本からステージングへ実際に書き込めた bytes、共通保存先の検証で読んだ bytes、旧保存先候補の照合で読んだ bytes を別々に数える。失敗・中断前に読んだ bytes も保持する。ローカルのステージングファイルへの再読取りは原本転送に含めない。

直近の試行または操作の終了時には `camera_import_metrics` の `last` へ、経路、終了状態、件数、bytes、一覧・履歴確認・全体の経過時間だけを保存する。試行終了は UI を終了させず、サービス全体の終了時だけ完了・取消・失敗を確定する。利用者の取消を同時に発生した転送エラーより優先する。

USB の再試行では、追加保存件数と原本・保存先の読取り bytes を操作全体で引き継ぐ。一覧・分類・処理済み件数と一覧/履歴時間は直近の試行の値とし、記録に scope、attempt、classificationScope=attempt、savedScope=operation、bytesScope=operation を明記する。保存・共通 receipt が完了した後で旧履歴の追記に失敗しても、保存済み件数を失わない。写真名、パス、接続元 ID、認証情報を記録しない。取消・失敗は完了として表示しない。共通履歴の回復処理が保存先を検証した場合も保存先読取りへ含める。

## 検証範囲

`CameraImportHistoryChecks.run(Instrumentation)` は、4800 件のメタデータ分類と少量追加、消失、曖昧な URI、削除記録、厳密確認、保存後サイズ、および独立したメモリ上の ContentProvider による一括照会・null・権限失敗・未公開・ゴミ箱を検査する。利用者の写真や既存履歴に合成データを追加しない。これは物理 SD の転送性能や実際の 4800 件の状態の検証とは分ける。
