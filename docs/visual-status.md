# 状態表示の契約と対象

Issue #17の現行契約。Claude完成版の[参照HTML](design/loupe-issue17-visual-status.html)に基づく。Android実装の確認範囲と限界は末尾に記す。

## 目的と境界

写真と操作に集中できるよう、可視の状態説明文を形・進捗・数値で伝える。短い操作名、機能見出し、写真メタデータ、入力条件、安全確認は残す。状態説明は読み上げに保持し、情報ダイアログに旧状態文を移すだけでは完了としない。

不変条件は原本・順位・タグ推論・選択・外部送信条件の保持。失敗を成功に見せず、再試行は明示操作で行う。前画面の遅延結果を新画面へ反映しない。件数未測定を0や100%にしない。JobStateのreadyとfailedは重なり得るため差引計算しない。

## 対象一覧

| 写真詳細 | 原本待ち、低解像度preview、原本失敗、情報シート内の状態文 | 写真名・寸法・カメラ情報、前後・共有、再試行、画質差の識別 |

## 検証の区分

変更前は0.17.20、25128PNA1Gで合成6枚・遅延loaderを使い、連写の読み込み文・失敗文・読込済み件数を確認した。変更後は短時間/長時間/失敗/再試行/中止/未知、320/400dp、文字倍率1/1.3、読み上げノードと実行可能な操作を確認する。実クラウドへの送信や写真原本の変更を合成検証で代用したと報告しない。

## 表示契約

- 状態の印は24dp枠/20dp描画、線1.8dp。実行=弧、待機=時計、停止=縦棒、完了=塗り丸チェック、部分失敗=チェック+警告、失敗=警告三角、認証=錠、未知=点線丸と疑問符。原因は通信/容量/権限/認証/TLS/接続先/共有先なし/形式/不明を別の印で示す。原因を推測して断定しない。
- 読込表示は400ms遅延、表示後は最低600ms、正常終了後150msで消す。失敗・写真切替は古い状態を即時置換する。8秒以降は高さ28dpの札に既知件数または経過分を併記する。遅延中もレイアウト位置を保つ。
- 成功・中止・登録済みは操作付近の40dpの丸に900ms、その後150msで消す。失敗は自動消去せず、48dp以上の操作領域から既存の再試行/ログイン等へつなぐ。再試行で原本送信などの確認を飛ばさない。
- 空状態は48dp点線枠と既存操作に置換する。#14の保持方針より、#17の全画面状態文廃止を優先する。入力の条件・安全確認は文章のまま保持する。
- 写真previewのみは格子印、原本失敗は格子と警告を残す。previewも表示できない場合は写真領域中央の警告と48dpの明示的な再試行ボタンから復帰する。写真変更は旧タイマー/表示/復帰対象を無効にする。
- 印の読み上げに状態・原因・復帰方法の全文を残す。polite通知は状態変化時に行い、単なる再描画で同文を繰り返さない。可視文字から状態を推測しない。
- 代表画面全体の写真/ヘッダ/dock配置は模擬。#8の全体再設計を先取りせず、状態部品と必要な復帰操作だけ適用する。

未計測件数のHTML例は既知の分子を含むが、現行JobStateがcountsKnown=falseなら分子も未知として「—」とし、推測値を使わない。共有準備にも実件数進捗が未提供なら不定進捗を使う。

## 実装の検証範囲

`ArchiveInstrumentation`の`visual-status`は、短時間の非表示、600ms保持、終了と旧状態の消去、8秒実待機時の幅保持、模擬61秒起点、既知件数を確認する。320/400dp・文字倍率1/1.3で共通状態と原因別の実機画像を保存する。

`VisualStatusFlowChecks`は、隔離した合成JPEG・失敗する共有writerを用い、実画面の原本欠落→復元→再試行、共有の中止・失敗・再試行での選択保持、タグ空入力→訂正→中止を検証する。合成写真名もUUID化し原本キャッシュとの試行間衝突を避ける。実データのタグ保存、外部共有・クラウド送信、通信障害、TalkBack音声を実施した検証ではない。

参照HTMLのRoboto指定はフォント同梱ではなく、ブラウザの代替フォントとAndroidの字形には差がある。描画方式による破線の端点や回転の位相差を、形の意味や復帰操作の不一致と区別する。
