# USBカメラ取り込み

カメラを接続し、写真・RAW・動画の新規分をLoupeに取り込める。旧CameraSyncの機種設定と取り込み履歴は、同じ端末で引き継げる。

- 現行の外観と標準部品は [Material 3 UI契約](material3-ui.md) に従う。参照HTMLは過去の設計記録として保持する。設定から接続の有無、進捗と最後の結果を確認できる。端末のUSB許可とハンドラ選択はAndroidに委ねる。
- MTPとUSBマスストレージの両方で機種ごとの履歴を使う。保存先はCameraSyncと同じMediaStoreのパス。公開済みメディアのみ履歴へ登録する。中断時は公開済み分を残す。
- 移行にはCameraSyncが書き込み中でない時点のSQLiteスナップショットを使う。機種とシリアル、ファイル名・サイズ・撮影日時で照合し、既存のLoupeの設定と履歴を優先する。エラー時は移行全体を取り消す。元のDB・アプリ・メディアは変更しない。
- 移行した機種のカメラ側削除はオフ。USB接続から始まる自動取り込みでは原本を削除しない。手動取り込みでカメラ側削除を指定した場合も、対応するMTP機種で保存と履歴登録に成功した原本だけを対象にする。

［その他］の設定から［カメラから取り込む］を開く。初回に対象形式を選び、次回からの自動取り込みを設定できる。カメラごとの端末保存先は最初の取り込み後に変更できる。自動取り込みを使う場合、旧CameraSyncがAndroidの既定ハンドラなら、旧アプリの設定で既定を解除し、次回の接続時にLoupeを選ぶ。旧アプリのストレージは消去しない。

［記録のファイルを選ぶ］で、旧アプリの書き込みが完了した時点の `history.db` のスナップショットを選ぶ。以前の名前・サイズ照合だけで記録された可能性がある `existing` 行は移行時に取り込み済みとは扱わず、次回に保存先との照合を行う。撮影済み動画もMediaStoreへ保存する。取り込んだ動画の一覧表示・再生は既存の動画機能に従う。

MTPで端末へ転送した長さがカメラの報告サイズと一致しない場合、保存済みとして扱わない。4GiB以上の動画で報告サイズが折り返す機種はUSBマスストレージ経路を使う。全形式のMTP列挙に失敗した場合は「新規なし」と表示せず、接続を再試行する。

USBマスストレージの写真は、端末の一時コピーの長さを確認した後、MTPと同じ不正なEXIF OffsetTimeの補正を行ってからMediaStoreへ保存する。正常なオフセットは保持し、カメラ内の原本と取り込み済みの写真は書き換えない。保存・失敗のどちらでも一時コピーを片付け、保存と公開が完了した写真だけを履歴へ記録する。動画は従来どおり直接ストリームで保存する。補正済み写真とカメラ原本の重複照合では、比較用ヘッダーだけを同じ補正状態にして比較する。写真本体の異なるバイトは一致と扱わない。

重複照合では、カメラ原本で不正だったOffsetTimeの項目だけを比較用コピー上でそろえる。取り込み済みヘッダーの有効なオフセットを使い、照合時の端末タイムゾーンには依存しない。元から正常だったオフセットや、それ以外のバイトの違いは一致と扱わない。

Loupeの一覧・最近の写真・連写は、読み取れた有効なEXIF撮影日時を共通の根拠にする。有効なEXIFがある写真では、MediaStoreの日時が無効でも取り込み後の更新日時へ退避しない。有効なEXIFがない写真では既存の日時による並びを保ち、撮影日時を推定して原本へ書き込まない。秒単位の時刻が同じ写真は既存のファイル名順を維持し、秒未満の撮影順を保証しない。日時の補正は再構築可能な閲覧索引だけに反映し、元のMediaStore、保存確認・削除判定用の写真レコード、順位・タグ・取り込み履歴は変更しない。索引の入力署名で日時の解釈を識別し、初回に索引を再構築する。EXIF解析は変更していないため、有効な既存の日時キャッシュは再利用する。クラウド原本の自動取得は行わない。

OM Digital Solutions／OlympusとPanasonicはAndroidのUSB接続ハンドラから自動取り込みできる。その他のBOT対応USBストレージ（カードリーダーなど）は、カメラ取り込み画面から手動で選ぶ。対象の保存媒体はexFATのDCIM。

対応するUSB機器が接続されている間、「すべての写真」「アルバム」の横に「カメラ」を表示する。タップで設定を開き、長押しで取り込む。長押しではカメラ側を削除しない。許可や初回設定が必要なら先に行う。写真選択中はタブ操作を無効にし、取り込み中の長押しは開始を重ねない。切断でタブを隠し、現在のライブラリ画面を保つ。

長押しで許可や初回設定の画面を開いた場合、長押しから始めた取り込みが成功（新規0件を含む）した時点で、その画面を閉じて元のライブラリに戻る。失敗や中止の場合は画面を閉じず、結果を確認して再試行できる。通常タップで開いた設定は自動で閉じない。

## 現行mainとの統合

- 目的: 既存の写真・動画・Nano Banana機能と、接続カメラの取り込み設定・履歴を一つのアプリで使える。
- 機能: USB接続時にカメラ操作を表示し、タップで設定、長押しで原本を削除せず取り込む。
- 要件: ギャラリーとアルバムの移動はnative Material TabLayoutを使う。カメラ操作では現在の選択先を変えず、切断時は操作を除き、取り込み中の再実行と写真選択中の操作を抑止する。
- 不変条件: 既存の動画・Nano Banana設定項目と権限を保持する。保存先 `camera_import` と `camera-import-history.db`（schema 4）を変えず、アプリアップデートで既存データを引き継ぐ。移行を自動で再実行しない。
- 事前条件: USB権限と初回設定が完了し、取り込みを開始できる。未完了なら既存の許可・設定経路へ進む。
- 事後条件: 設定タップは元のギャラリー/アルバム選択を保持する。長押しは新規取り込みを一度だけ開始し、原本を削除しない。切断後の再接続でも操作を復元する。
- UI: カメラ取り込み設定はAppCompatActivity、MaterialButton、MaterialSwitchと既存のMaterialダイアログを使用する。カメラ操作は常に未選択のボタンとして読み上げ名・取り込み状況・削除なしの長押しアクションを提供し、48dp以上の操作領域を保つ。
- 検証: 320dp・文字倍率1.3の合成コンポーネント検査、接続/切断/再接続、選択維持、タップ/長押し、進行中・選択中の抑止を検査する。エミュレータ結果は物理カメラ/MTP/USB転送とTalkBack音声の検証を代替しない。
