# 個別写真から現像と外部編集を開く

対象: [Issue #51](https://github.com/ktnyt/Loupe/issues/51)、[Issue #53](https://github.com/ktnyt/Loupe/issues/53)、[Issue #181](https://github.com/ktnyt/Loupe/issues/181)。編集入口とコピー保全の契約。内蔵現像は[RAW現像の契約](raw-editor-contract.md)に従う。市販・一般配布の外部アプリでの編集と保存は未確認。

## 目的・機能・要件

個別写真を見ながら、端末の写真編集アプリでその写真の編集を開始できるようにする。
利用者の要件はツールバーへの「編集」追加と、狭い画面で二段に分けることの許容。
普段使う編集アプリを選んで記憶し、後から切り替えられるようにする。

MainActivityの通常表示・比較/結果からの閲覧と、TagActivityの写真閲覧を対象とする。
写真を主役にする黒背景、日時、fit表示、既存操作、標準Backを保持する。

## 契約

- 不変条件: Loupeのオリジナル・順位・タグを書き換えない。外部アプリに渡すのはオリジナル形式の一時コピーで、URIへの一時的な読み取り権限だけを付ける。書き込み権限や永続権限は渡さない。
- 事前条件: 対象写真を個別表示中で、同じ画面からの編集準備が実行中でないこと。
- 事後条件: 既定を選ぶまでは通常タップで選択ダイアログを開く。選択したアプリの起動に成功したら既定として記憶する。既定がある場合は通常タップで直接開く。
- 選び直し: 長押し・読み上げのカスタム操作「編集アプリを選ぶ」・Mainの情報シートから選択ダイアログを開く。「次回以降もこのアプリで開く」のチェックを入れたときだけ選択を既定にする。チェックを入れない選択は今回のみ。既定が削除・無効化された場合、写真の形式に対応しない場合、署名を照合できない場合は通常タップで候補を出す。ダイアログのキャンセルや起動失敗では既定を保持する。
- 候補: Loupeの内蔵編集と、写真の元形式のMIMEとコピーのcontent URIを扱える外部アプリ。外部アプリが `ACTION_EDIT` と `ACTION_VIEW` の両方に対応する場合は `ACTION_EDIT`、`ACTION_VIEW` のみに対応する場合は `ACTION_VIEW` で開く。各候補はアプリ単位で表示する。外部アプリの既定にはパッケージ名と署名のSHA-256を保存し、一時コピーを渡す直前にも選んだアプリの署名を照合する。同じ表示名がある場合は外部アプリにパッケージ名を添え、選択したアプリだけにコピーを渡す。
- 保存: 内蔵現像はオリジナル非変更の別JPEG保存。外部編集結果の保存先・方法は編集アプリが扱う。Loupeへ戻るだけでは保存完了と判定せず、編集結果の自動取り込みやオリジナルの上書きは行わない。
- 非同期処理: コピー準備をUIスレッド外で実行し、連打を抑止する。準備中のキャンセル、画面のdetach、ウインドウのフォーカス喪失で準備を中止し、復帰後にも編集先を遅延起動しない。
- 失敗: オリジナルの取得・コピー・空き容量・権限・編集先の起動失敗を、写真画面に戻って再試行できる形で扱う。クラウドオリジナル取得は既存の取得・検証契約に従う。
- 計測: ボタン操作からコピー完了、選択ダイアログ表示・編集先起動までを分離する。選択ダイアログ表示・編集先起動を編集結果の保存完了とは扱わない。写真オリジナル・URI・ファイル名を計測ログへ加えない。

## UIの設計条件

選択ダイアログは[Material 3 UI契約](material3-ui.md)と #181 に従う。候補をアプリ名で読み上げ、各行に48dp以上の操作領域を確保する。初回は「ロングタップで編集ソフトを変更できます」を表示する。長押し時は未チェックのチェックボックスを表示する。

- 「編集」は鉛筆の線アイコンと短いラベルで表示する。
- Mainは共有の直前、Tagはタグ操作の直前に追加する。他の操作の順と表示条件を保持する。
- 現在の24dpアイコン、12sp文字/16sp行高、最低64dp高、セル左右2dp/上下4dp、footer下20dpを基準とする。
- 文字の実測幅とpadding、最低48dpの操作幅に基づき、一段に収まらなければ順序を保って二段へ分ける。省略や文字縮小で収めない。
- タグの付ける/外す、拡大/全体の表示変更や文字拡大時にも再配置する。
- 通常7操作、比較/結果4操作、Tag5操作。比較中の「この写真を選ぶ」は別の主ボタンとして保持する。
- 写真の読込、編集準備中、失敗、キャンセル、復帰の状態を扱い、既存の状態表示と読み上げを維持する。

## 実装方針

既存 `SharePreparation` とread-onlyの `ShareProvider` を利用する方針。
編集先起動とライフサイクルの処理をMain/Tagで共通に扱い、既存の共有契約は変更しない。
Main/Tagはアプリの既定を共有する。read-only入力から別保存する編集先を対象とし、入力への書き戻しを要求するアプリとの互換性は保証しない。

準備は400ms経過後に同じセルの回る印と「中止」で示す。400ms未満の連打は無視し、表示後の再タップで中止する。失敗は同セルの失敗印と読み上げで示して再試行できる。Tagの保存中は編集も無効にする。

一段が収まらなければ列数を操作数の半分の切り上げにし、二段目は同じセル幅のまま中央へ配置する。拡大/全体、タグを付ける/外す、編集/中止は長い方の文字幅で判定し、状態切替で段数が揺れないようにする。

## 検証条件

320/400dp、文字1/1.3倍、640/844dpの縦画面で写真領域・ラベル・操作域・全操作への到達を確認する。
Main通常/比較/結果、Tagの付け外し、前後の無効状態を含む。
合成JPEG/RAW、準備失敗、編集先の起動失敗、キャンセル、画面離脱、編集先からの復帰、オリジナル不変を検証する。
選択と記憶、今回のみ開く操作、候補の形式対応、選択の取り消しをAndroid上で確認する。独立UI評価・Cold Review・Security Reviewを行う。

## 対応の判定

合成写真を使い、専用Androidエミュレータの400dp/font 1.0と320dp/font 1.3で、初回のアプリ選択、通常タップでの再起動、長押しでの今回のみの起動と既定変更、キャンセルを確認した。保存した既定アプリが見つからない場合、対象のMIMEに対応しない場合、保存した署名情報が欠けているか一致しない場合に、選択画面が開くことも確認した。署名の欠落と不一致は保存値を使った合成検査である。

別プロセスで動く検査用アプリがコピーを読み取れ、書き込み権限が付与されていないことを確認した。渡した元形式のMIME、元ファイルとコピーの同一性、オリジナルが変更されないこと、準備の中止と遅延起動の抑止、失敗後の再試行も確認した。物理端末、一般配布の外部アプリでの編集と保存、実写真のRAW、署名の異なる実APKへの差し替え、署名ローテーションや複数署名の実APK、TalkBackの音声は未検証。

編集ボタンとコピー保全の経緯はIssue #51、アプリ選択と既定の記憶の経緯はIssue #181に記録する。
