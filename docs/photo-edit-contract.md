# 個別写真から端末の編集アプリを開く

対象: [Issue #51](https://github.com/ktnyt/Loupe/issues/51)。実装前に定めた契約を実装し、合成写真で確認している。実際の編集アプリでの読み込み・保存の互換性は未確認。

## 目的・機能・要件

個別写真を見ながら、端末の写真編集アプリでその写真の編集を開始できるようにする。
利用者の要件はツールバーへの「編集」追加と、狭い画面で二段に分けることの許容。
端末の編集アプリを開くことは利用者へ確認済み。

MainActivityの通常表示・比較/結果からの閲覧と、TagActivityの写真閲覧を対象とする。
写真を主役にする黒背景、日時、fit表示、既存操作、標準Backを保持する。

## 契約

- 不変条件: Loupeの原本・順位・タグを書き換えない。外部アプリに渡すのは原本形式の一時コピーで、URIへの一時的な読み取り権限だけを付ける。書き込み権限や永続権限は渡さない。
- 事前条件: 対象写真を個別表示中で、同じ画面からの編集準備が実行中でないこと。
- 事後条件: コピーの準備が完了してから `Intent.ACTION_EDIT` のchooserを開く。写真の形式に対応する編集アプリを選べる。RAWも元形式で渡すため、RAW対応の編集アプリが必要。
- 保存: 編集結果の保存先・方法は編集アプリが扱う。Loupeへ戻るだけでは保存完了と判定せず、編集結果の自動取り込みや原本の上書きは行わない。
- 非同期処理: コピー準備をUIスレッド外で実行し、連打を抑止する。準備中のキャンセル、画面のdetach、ウインドウのフォーカス喪失で準備を中止し、復帰後にも編集先を遅延起動しない。
- 失敗: 原本の取得・コピー・空き容量・権限・対応アプリなしを、写真画面に戻って再試行できる形で扱う。クラウド原本取得は既存の取得・検証契約に従う。
- 計測: ボタン操作からコピー完了、chooser起動までを分離する。chooser起動を編集結果の保存完了とは扱わない。写真原本・URI・ファイル名を計測ログへ加えない。

## UIの設計条件

元S08と `design/loupe-photo-viewer.html` の既存配置を保持し、[Claudeの編集ボタン設計](design/loupe-photo-edit-toolbar.html)を追加部分の基準とする。HTMLは合成でありAndroidの動作保証ではない。

- 「編集」は鉛筆の線アイコンと短いラベルで表示する。
- Mainは共有の直前、Tagはタグ操作の直前に追加する。他の操作の順と表示条件を保持する。
- 現在の24dpアイコン、12sp文字/16sp行高、最低64dp高、セル左右2dp/上下4dp、footer下20dpを基準とする。
- 文字の実測幅とpadding、最低48dpの操作幅に基づき、一段に収まらなければ順序を保って二段へ分ける。省略や文字縮小で収めない。
- タグの付ける/外す、拡大/全体の表示変更や文字拡大時にも再配置する。
- 通常7操作、比較/結果4操作、Tag5操作。比較中の「この写真を選ぶ」は別の主ボタンとして保持する。
- 写真の読込、編集準備中、失敗、キャンセル、復帰の状態を扱い、既存の状態表示と読み上げを維持する。

## 実装方針

既存 `SharePreparation` とread-onlyの `ShareProvider` を利用する方針。
編集先起動とライフサイクルの処理をMain/Tagで共通に扱い、既存の共有契約は変更しない。
Main/Tagからの起動処理とコピー/権限/中止/再試行を実装している。read-only入力から別保存する編集先を対象とし、入力への書き戻しを要求するアプリとの互換性は保証しない。

準備は400ms経過後に同じセルの回る印と「中止」で示す。400ms未満の連打は無視し、表示後の再タップで中止する。失敗は同セルの失敗印と読み上げで示して再試行できる。Tagの保存中は編集も無効にする。

一段が収まらなければ列数を操作数の半分の切り上げにし、二段目は同じセル幅のまま中央へ配置する。拡大/全体、タグを付ける/外す、編集/中止は長い方の文字幅で判定し、状態切替で段数が揺れないようにする。

## 検証条件

320/400dp、文字1/1.3倍、640/844dpの縦画面で写真領域・ラベル・操作域・全操作への到達を確認する。
Main通常/比較/結果、Tagの付け外し、前後の無効状態を含む。
合成JPEG/RAW、準備失敗、対応アプリなし、キャンセル、画面離脱、編集先からの復帰、原本不変を検証する。
設計HTMLと実機を比較し、独立UI評価・Cold Review・Security Reviewを行う。

## 対応の判定

目的・要件・契約に対応するMain/Tagの編集入口と配置を実装している。合成写真で原本不変、read-only権限、準備中止、遅延完了、失敗再試行を確認。400dp/文字1.0と320dp/文字1.3でMainの操作順と配置・既存操作を確認。外部編集アプリの実起動/保存、実写真RAW、TalkBack音声、その他の寸法・状態は未検査。
工程の経緯、阻害要因、再開情報はIssue #51へ記録する。
