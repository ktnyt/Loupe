# 写真の保存先と取り込み済み写真の移動（#162）

## 目的と対象

端末内部の空きを確保しながら、Loupe で取り込む写真を引き続き閲覧・整理できるようにする。利用者は今後の保存先を選べる。保存先の設定とは別に、Loupe の取り込み履歴にある既存写真をまとめて移動できる。端末のライブラリ全体の移動は対象外とする。

## 保存先の選択

- 内部ストレージを既定とする。Android が提供する書き込み可能な着脱式 SD カードの MediaStore ボリュームを選択できる。ボリュームの識別子を保存し、次回起動時も同じカードを参照する。
- USB、Wi‑Fi、自動取り込みの写真と動画は開始時の保存先を確定し、同じ処理中は変更しない。保存中の取り込み記録は保存先ボリュームを保持し、再開時もそこを参照する。
- 選んだカードが未接続、読み取り専用、容量不足の場合は保存失敗を通知し、内部ストレージへの切り替えは利用者が行う。カードが見えない間も取り込み履歴を保持する。
- 保存先を変更しても既存ファイルは移動しない。端末上の写真ファイルを作る編集、Nano Banana の保存経路は、同じ保存先選択を適用できるものを対象とする。

## 既存写真の移動

- 前提は、移動先が書き込み可能で、取り込みや別の移動が進行中でなく、利用者が移動先と対象件数を確認して実行すること。
- 取り込み台帳または旧取り込み履歴が実ファイルを指し、Loupe が所有し、選択先とは異なるボリュームにある写真を対象にする。同一 URI は一度だけ処理する。旧取り込み履歴だけを根拠にする場合は、保存時のファイル名、サイズ、記録がある場合の撮影日時を照合する。元アプリが所有する旧写真、実ファイルを特定できない履歴、参照先カードが外れている写真は、権限や存在を推定して削除せず、理由と件数を表示する。旧写真を移動する場合は Android の個別許可が必要になる。
- 移動先の空き容量を確認し、元の撮影データをそのままコピーする。未公開行を使用し、SHA‑256 とサイズを読み戻して一致を確認してから公開する。元のフォルダ、ファイル名、メディア種別、撮影日時を維持する。撮影日時がない写真は Loupe の一覧で移動前の更新日時を使って並べる。Android が索引するファイル自体の更新日時はコピー時に更新される場合がある。MediaStore が同名を調整する場合も既存行を上書きしない。
- 公開後、取り込み済みを判定する台帳と旧履歴の参照先、およびランク、タグ、共有履歴が参照する写真の論理識別子を更新する。取り込み対象の元 ID、取り込み件数、ランク、タグ、共有履歴を引き継ぐ。同じファイルに読み取り許可済みフォルダの参照がある場合は、移動前に表示していた写真の識別子を引き継ぐ。E2 の削除許可は以前の URI に対応するため引き継がない。
- 元データを削除する前に、移動先の公開状態と SHA‑256 を再確認する。元データと移動後の取り込み記録も照合し、削除直前に移動先の公開・更新状態を確認する。所有権と取り込み由来を確認できた元データだけを削除する。成功は削除結果を確認してから記録する。取り込み履歴に属さない写真には書き込まない。
- 1枚ごとの状態を内部ストレージに永続化し、公開・参照先更新・元データ削除の途中で終了しても同じ移動を再開できる。照合、空き容量、カードの状態、権限、削除のいずれかに問題があれば元データを保持する。再試行で既に確認した公開済みデータの重複は作らない。中止は安全な境界で処理を止め、完了した移動は保持する。中断した移動は再開または終了できる。終了時には完了分と元データを保持し、未完了の履歴更新を戻す。検証済みの移動先ファイルも残す。
- 同名の別写真を異なるボリュームに置いても、両方がライブラリに表示され、ランク、タグ、共有履歴は混同されない。

## 移動の照合と速度の計測

- 同じ写真を連続して処理する間は、公開後の全量照合結果を、その直後の履歴更新前の確認でも使える。再利用の前に所有者、公開・ゴミ箱状態、メディアの更新状態が一致することと、中止されていないことを確認する。更新状態が変わっていれば全量を読み直す。更新状態の一致だけをファイル内容の一致の証明にはしない。
- この証拠は処理中のローカル変数だけに置き、次の写真、呼び出し、中断後の再開には持ち越さない。履歴更新後・元ファイル削除前の移動先の全量照合と、元ファイルの全量照合、削除直前の状態確認は省略しない。
- 診断には処理全体とコピー、同期書き込み、照合、公開、履歴更新、削除の時間、および成功した移動先全量照合の回数とバイト数を固定名の集計値として残す。写真名、URI、パス、ハッシュ、画像データを記録しない。診断は既存のデバッグ用ローカルログに限定する。
- 比較では同じ端末、保存先、形式、枚数、サイズ、診断設定を使い、準備・対象抽出・移動完了・後片付けの時間を分ける。合成写真やエミュレータの結果を実SD・利用者の写真での速度として報告しない。個別区間の短縮だけで操作全体の改善と扱わない。

## 画面と操作

- 全般設定とカメラ取り込み設定から保存先にアクセスできる。選択中の保存先を文字で表示し、Material 3 の単一選択ダイアログで選択する。カードを選べないときは状態と必要な操作を示す。
- 既存写真の移動は独立したアクションとし、移動先、対象件数、移動できない件数を確認してから開始する。実行中は進捗と中止操作を示し、競合する取り込み・保存先変更・移動を許可しない。
- 終了時は完了、未処理、移動不可の件数と、失敗時に取り得る操作を表示する。画面を作り直しても進捗を表示し、アプリが終了した場合は次回に再開できる。
- Material 3 の標準操作と読み上げ用ラベルを使う。タッチ領域は 48dp 以上とし、表示幅 320dp、文字拡大 1.3 倍でもラベルを折り返して必要な操作に到達できるようにする。状態は色だけで伝えない。

## 検証

- Android の内部ストレージと着脱式 SD カードについて、保存先選択、各取り込み経路、新規保存、移動前後の件数と SHA‑256、再取り込み防止、ランク・タグ・共有履歴、同じ名前の別写真を確認する。
- コピー後、参照先更新後、削除後の中断を再現し、再試行で重複や消失が生じないことを確認する。カードの取り外し、読み取り専用、空き容量不足と、Loupe が所有しない旧写真も確認する。
- Android UI の通常幅・文字サイズと狭幅・拡大時の表示を取得し、独立したレビューを行う。自動検証と実カードでの検証を区別する。

検証条件とAndroid画面の記録は[検証画面](design/photo-storage/README.md)を参照する。試行・レビュー・配布の進捗は #162 に記録する。
