# #166 挿し替えたSDカードの取り込み元確認

対象は `166/swapped-source-detection` の基点 `99aed7a`。実装前の契約。今回指定された非保存先カードからの新規取り込みを扱う。#176 の旧取り込み元との同一性は未確認であり、この確認に流用しない。

## 文脈と根拠

- 実機で、保存先を維持したまま別の非保存先カードがマウントされている。登録済みの取り込み元はマウントされておらず、現在のカードと一致しない。このカードの MediaStore 画像・動画一覧はともに0件だった。利用者からは新しいカードに写真があるとの申告がある。選択したDCIMのDocumentsProvider一覧とアプリで表示された文言は、現時点の手元の記録では未確認。
- **接続された取り込み元と登録済みフォルダの表示が一致しない。** 設定画面の「フォルダを選択済み」は登録URIと永続読み取り許可の一致で表示される。カードのマウントとフォルダへの到達は確認していない。手動の取り込みはその登録で進み、安全確認で停止すると文言だけを表示する。接続時のクイック経路には、到達できない登録に対してフォルダ選択を開く分岐がある。根拠は `CameraImportActivity.java:247–267, 420–431, 908–938, 980–1003` と `CameraQuickImportSources.java:23–45`。
- **読み込み中の一覧が空として扱われるコード経路がある。** `CameraDocumentSource.list/scan` は子カーソルのロード中・エラーの通知を確認せず、返った行で一覧を作る。サービスは一覧の走査が成功扱いで候補が0件なら「0枚追加・0枚取り込み済み」で終わる。種別の選択で0件になった場合も同じ。実機でこの経路を通ったかは未確認。根拠は `CameraDocumentSource.java:31–57` と `CameraDifferentialService.java:234–267`。
- **フォルダ選択の確定は自動取り込みにも影響する。** 設定の選択画面とカード確認を伴う選択画面は、最終の取り込み操作より前に `sd_tree_uri` と永続read grantを保存し得る。 `storeSdTree` は監視サービスも設定し直す。WATCH自体は取り込みを開始しないが、`sd_auto=true` のmount receiverは受け取ったイベントのカードを問わず、その時点の保存済みtreeで開始を要求する。現行コードには選択中の確認画面とこの開始要求の間の排他がない。実機設定値はtrue。検証ではこのフォルダ選択をまだ確定していない。根拠は `CameraImportActivity.java:811–829, 954–958, 1004–1015` と `CameraDifferentialService.java:43–69`。
- **一覧の列挙と原本のMediaStore登録は別段階。** SDの一覧はDocumentsProviderから列挙する。MediaStoreの原本マッピングは候補ができた後に照合する。対象文書が存在し、同じボリューム・フォルダ・名前の行を完全なクエリで確認して0件なら、現行コードは `INDEX_PENDING` を返す。権限・別カード・曖昧なマッピングは別の失敗条件。今回のボリューム全体のMediaStore 0件から、DCIMが空または個別ファイルが未登録とは判定できない。根拠は `CameraDocumentSource.java:105–205, 215–248` と `CameraDifferentialService.java:244–253`。

## 目的: 挿し替えたカードの写真を、選んだカードから安全に取り込める

- **機能** 利用者は現在の取り込み元と保存先を確認し、登録したカードが取り外されていたら、新しいカードのDCIMを明示選択して同じ取り込みに戻れる。写真の確認中、未登録、対象なし、確認済みの状態を見分けられる。
- **要件** 登録、読み取り許可、接続、一覧、原本マッピング、取り込み結果の各段階に対応した表示と、再選択または再確認の操作がある。取り込み元の選択は利用者が行う。原本の取得方法、バイト照合、保存先の固定、取り込み履歴と重複防止の条件を維持する。
- **契約** 下記の取り込み元選択、一覧の確定、取り込み結果の3条件を満たす。画面が「なし」と判定できるのは、選択されたフォルダの関連範囲を最後まで確認できた場合だけ。
- **対応の判定** 状態の案内と不完全な一覧の判定は現行コードと不一致。新カードの実機でどの経路を通ったか、実装後の動作は未検査。

### 目的: 選択した取り込み元と保存先を取り違えない

- **機能と要件** 設定の手動開始、接続時の開始、権限付与後の再開で同じ元カード確認が働く。状態は未登録、許可なし、登録先の未接続またはカード変更、登録済みだがフォルダに到達できない、保存先と同一、利用可能を区別する。
- **不変条件** 汎用リーダーから外部カードへ取り込む際は、外部ストレージプロバイダの選択済みDCIM tree、そのUUIDに一意に対応する読み取り可能な非仮想リムーバブルボリューム、変更されていない別の保存先を使う。確認済みのtree URIと権限を維持する。未選択のカードや保存先へ自動で切り替えず、USBの強制claimを使わない。
- **事前条件** 再選択は利用者操作に紐づく。未接続の登録は利用不可と示し、同じ操作からフォルダ選択に進める。候補の残りが1枚でも選択を代行しない。保存先と同じカード、非DCIM、権限不足、フォルダ選択の取消では、以前の登録を上書きしない。
- **事後条件** 選択直後は、受け取った一時的な読み取り許可を使って元と先を表示する。手動取り込みの最終確認、または取り込み元を登録する独立した確定操作まで、新カードを `sd_tree_uri` として公開せず、自動監視に渡さない。登録と自動取り込みの関係が分かる形で確定を受ける。自動取り込みは有効な登録のみを再利用する。登録変更、カード取り外し・入れ替え、保存先変更、権限失効、操作取消を検知したら、以前の一覧確認・権限要求からの戻り・操作結果を失効させる。同一カードの同じUUIDへの再接続も取り外しを検知した時点で古い依頼を無効にする。実行直前に既存の元・先確認を再実行する。
- **実装候補** 現行の `sourceGeneration`、キャンセル、`MountedCameraCard` のボリューム確認を再利用。保存済みgrantの検出と利用可能性を別の状態として返し、手動・クイックの状態表示に反映する。作業中の確認を続行できない場合は既存の確認経路へ戻る。

### 目的: 調査中のフォルダを空として確定しない

- **機能と要件** 選択したDCIMをメタデータで列挙し、確認中、一覧確認失敗、対応する写真なし、選択種別なし、候補ありを表示できる。
- **不変条件** 候補数は現在のカードと現在のtreeに対するDocumentsProviderの確定結果から得る。MediaStoreの0件、登録なし、nullカーソル、例外、ローディング、エラー、期限切れ、走査上限、キャンセルから空確定を作らない。部分結果を取り込み対象として確定させない。
- **事前条件** 読み取り許可と元カード・保存先を確認した依頼だけを走査する。ロード中とエラーの情報を、空のカーソルと行ありのカーソルの両方で確認する。キャンセルか再試行時は、古い走査結果を画面に適用しない。
- **事後条件** 正常に最後まで確認したフォルダに対応する写真がなければ、選択範囲に限って「取り込める写真がありません」と案内できる。JPEG/RAWの絞り込みで0なら選択種別の変更を案内する。動画だけの場合は現行経路の動画非対応を示す。未完了の一覧には確認中または再試行の案内を出す。いずれも取り込み済み件数に数えない。
- **実装候補** `CameraDocumentSource.scan` の列挙完了またはエラーを `CameraDifferentialService` へ伝える。同じフォルダのメタデータを画面用と実行用に無条件で二重走査しない。現行の走査予算を維持し、画面をブロックしない。

### 目的: 見つけた写真の未登録と取り込み済みを区別する

- **機能と要件** フォルダにある写真で原本取得条件を満たせない場合、条件に応じて再確認や権限の復旧を案内する。取り込み済みは既存履歴の条件を通過した候補に限る。
- **不変条件** MediaStore原本取得の権限、指定ボリュームへの一意なマッピング、`setRequireOriginal`、新規・変更・未知・明示確認のバイト数・全量SHAと履歴確認を維持する。通常SDの再取り込みで内容を読み直さず省略する場合は、下記の高速差分の条件を追加で満たす。中断や未登録の候補を新規保存または取り込み済みと記録しない。確認済み候補の処理結果を、未確認の候補に適用しない。
- **事前条件** 個別メディアの未登録は、有効な元カードと権限、完全な文書メタデータ、正確な元ボリュームへの完全な照会で該当行なしを確かめた場合だけ報告する。権限不足、登録確認の失敗、別カード、同名の曖昧な行は既存のエラー分類を維持する。
- **事後条件** 候補がある未登録ケースは、写真の存在とAndroid側の登録が未確認であることを示す。同じカードで再確認できる。処理済みの写真がある場合は、未処理のエラーで件数を巻き戻して全件0にしない。未登録のままSAFのストリームへ切り替える変更と強制インデックス起動は今回の案に含めない。
- **未決定** 実機でカードを維持してもAndroidのインデックスが生成されない場合、運用上の再確認で復帰するかを測定する。別の原本取得経路が必要なら、EXIF等の原本性、元・先の同一性、重複防止を同等に保証する方法を別途設計する。

## 変更前の実機確認とUI契約

0.31.50の通常設定画面で、登録元カードが未接続なのに「フォルダを選択済み」と表示され、手動の取り込み操作が有効であることを確認した。新しい非保存先カードはmountedだが、MediaStoreのimage/videoは0件。直近の保存済みSD計測は以前の977件の一致結果であり、今回の新カードで0件の走査が完了した証拠ではない。SHELLでのDCIMメタデータ集計は到達不可という結果であり、空とは判定しない。現在のDocumentsProviderの完全な列挙結果はまだ未確認である。

利用者の「なし判定」の正確な入口は確認を依頼中。取り込み経路の不具合として、実測できた古い登録の利用可能表示と、静的に確認した未完了一覧の確定扱いを先に修正する。入口が別だと分かった場合は、その経路も検証する。修正しただけで今回の新カードの写真検出が成功したとはしない。通常版で正しいカードを明示選択し、完全な一覧、原本マッピング、実際に処理できる範囲を確認して初めて完了を判定する。

UIは `docs/material3-ui.md` と既存の設定・Material dialogを使う。状態は確認中、未登録/許可不足、登録元未接続/変更、フォルダ到達不可、利用可能、一覧未完了/エラー、完全な対象なし、選択種別なし、原本登録待ち、履歴確認済みを区別する。空確定前に0件完了や取り込み済みと表示しない。元と先を区別し、再選択・再確認・取消の操作を48dp以上で用意する。状態は文字拡大で折り返し、読み上げを過剰に繰り返さず、確認中は不定進捗を使う。新しい汎用プランキャッシュや無関係なレイアウト改修は行わない。UI captureと独立UI/UXレビューを実装後に行う。

## 写真1枚の公開と読取許可の失効

SDからの読み出し中、読み出し完了時、既存履歴の再利用・参照更新・採用、保存先への公開を始める直前に、選択元の永続読み取り許可を確認する。公開前に失効したら、その写真の履歴を確定せず、所有する未公開の仮行だけを片付ける。原本と以前の取り込み履歴を保持する。

検証済みの公開を許可して、台帳のREADYを永続化する直前を1枚の確定境界とする。拒否された写真をREADYにしない。READYの永続化後は、許可失効と競合しても、保存済みファイルを履歴なしで残さない。既存の公開・台帳確定・復旧の手順を完結するか、復旧可能な記録を保持する。完了した最後の写真を後から失敗にせず、次の写真を始める前に許可を再確認して停止する。キャンセル、元・先の固定、バイト照合、失敗時の復旧条件を維持する。

## 保存先が失われた履歴の置き換え

以前の保存先が見つからなくても、既存contentsとreceiptsを再保存の準備で消さない。マウント済みの旧保存先を完全な照会で不在と確認し、最初に選んだcontents全項目の証拠をpendingのreplacement_witnessへ保存する。CameraImportLedgerのDBはv3とし、v1/v2からnullable TEXTを追加する。通常確定と再起動後の復旧は、この同じ証拠を条件に比較し、検証済みの新しいdest_uri/stored_sha/stored_bytesだけを更新する。既存receiptと時刻、contentsの元SHA/サイズ/種別/グループ/作成時刻を保持する。

旧pendingで証拠がNULLの場合は、現在の別の履歴を後付けの比較元にしない。現在のcontentsがない通常新規、または同じ確定先・検証済みの内容が既に存在する冪等な復旧だけを許可する。不完全照会、比較元の変化、未承認の公開済み行では写真と復旧記録を保持する。未公開行の削除も、所有者・pending・非ゴミ箱・固有仮名・フォルダ・確認時の世代を条件に行い、変化があれば削除や記録消去をしない。

## 通常SAF/SD再取り込みの高速差分

通常モードだけ、元カードID・相対パス・サイズ・正の利用可能な更新日時が完全一致するoriginal-byte-v1の受領記録と、以前の全量照合で記録した保存先の状態を使う。元tree・永続read grant・元と先・取り外し世代・原本MediaStoreマッピングは省略せず、履歴確認済みと決める直前にも元の許可を確認する。高速判定ではcontentsやreceiptsを追加・更新しない。

保存先は具体的な画像URIで、現在の完全な単一行がID・volume・owner・サイズ・公開済み・非ゴミ箱の条件を満たし、記録したepoch・追加世代・更新世代と一致することを要する。集約URI、未知値、欠落、変更、曖昧な照会、明示的な「内容も確認する」は既存の内容照合へ戻す。不完全照会を不在や再保存の根拠にはしない。

CameraImportLedger v4に、source_shaを主キー・外部キーとし、検証済み保存先URI、stored_sha、stored_bytes、epoch、追加世代、更新世代を保持する表を追加する。v1〜v3からは空で移行する。全量SHA・サイズが一致し、読取り前後の公開済み保存先メタデータとcontentsの行が変わらず、元の許可が有効な場合だけ証拠を保存する。現在のメタデータだけから古い証拠を後付けしない。古い写真や新規保存で証拠がなければ、最初の再確認だけ従来の保存先全読を行う。

分類中はphotoHistoryでchecked/selected/knownを示し、完全な分類後にneedsContentを確定する。高速一致した327件だけならknown=327、needsContent=processed=contentMatches=0、元と先の読取りも0とし、結果は327枚取り込み済みとする。実際にバイトを照合した件数と履歴だけで省略した件数を混同せず、metadata照会はhistoryMsへ計上する。

この省略は同じ写真を追加するかの判定であり、バックアップ整合性、写真の移動・削除の許可には使わない。世代が変わらない同サイズの上書きは通常判定では検出できない。明示確認は元と先の全量SHAで検査し、Wi-Fi/USB/MTP、復旧と移動・削除の検証は維持する。
