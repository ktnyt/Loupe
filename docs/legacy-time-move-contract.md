# 旧取り込み写真の移動前確認

撮影日時の秒が履歴と1秒ずれる写真や、撮影日時を取得できない写真も、端末の原本と検証済みバックアップが同じと確認できれば移動できる。現行の取り込み履歴およびカメラのチェックサムで確認できる写真には既存の条件を適用する。

## 照合条件

- 候補は、内部ストレージの取り込みフォルダにある公開済みの写真で、Loupeが所有し、読み書きと原本の参照が可能なものに限る。実ボリューム、集約URIの一意性、取り込み履歴の1件への紐付き、カメラの記録との矛盾がないことを確認する。
- 履歴の撮影時刻は正の偶数秒とする。写真の時刻はその1秒後か、不明を示すNULL、0、-1に限る。元のファイル名または取り込み時に付けた名前に一致し、同じサイズである必要がある。ファイルの更新時刻は取り込み時刻と一致し、追加時刻は取り込み時刻の1秒前から取り込み時刻までとする。
- 検証済みのE2記録のフォルダ、名前、サイズ、更新時刻、追加時刻が端末の写真と一致し、確認日時が取り込み時刻以降である必要がある。現在のアプリからMediaStoreのバージョンを取得し、写真が追加されてから現在までの世代番号について、E2記録のキーを再構成する。世代差は256以下とし、範囲を最後まで確認して一致が1件の場合に限る。照合処理の上限に達した場合や中断した場合は、確認できなかった写真を元の場所に残す。

## 確認と移動

保存場所の一覧はメタデータの照合まで行う。移動の操作では、候補ごとに原本を最後まで読み、バイト数とSHA-256を検証済みE2記録と比較する。読み取りの前後で写真、MediaStoreのバージョンと世代、所有者、アクセス権を確認する。この確認では移動先にファイルを作成せず、履歴やE2の記録を更新しない。確認できた枚数と容量、対象外の項目を表示し、利用者が確認画面で「移動」を選んだ場合に限り、その確認結果で移動を始める。確認は中止できる。

移動中の記録には、確認した旧取り込み履歴とE2記録の根拠を保持する。途中で終了して再開しても、この履歴を別の取り込み記録で代用できない。コピーしたバイトがE2記録と一致することを確認し、公開前と公開後の照合、参照先の更新、元の写真の再照合を経てから削除する。E2記録を移動先の参照に書き換えたり、クラウドの整理権限として扱ったりしない。
