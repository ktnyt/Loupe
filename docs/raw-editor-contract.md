# 実験的な内蔵RAW現像

対象: Issue #53。目的と契約。Lightroomとの画質・数値互換は保証しない。

## 目的・要件・状態

Android端末内でRAWを現像し、主題を拡大して質感を決め、全体の明暗・色を整える流れと2DUIを評価する。7タブ（WB・質感・トーン・明るさ・明暗・白黒・カラー）と写真上の透明2DUIはissueに記載した利用者指定。長辺2048px以下の初期実験、WBは撮影時基準からの相対調整、明度は中間調中心の調整、色別調整は後続候補、という具体化は今回の実験範囲。

## 原本・入出力

- 原本は読み取り専用。ローカルURIからアプリ専用の一時コピーを作りRAWデコーダーへ渡す。原本・URI・パス・写真内容をログや外部サービスへ送信しない。
- LibRawで実RAWの画素を展開する。埋め込みJPEGを現像結果と呼ばず、RAW読込失敗をJPEGへの代替で隠さない。JPEG入力はJPEGとして区別。
- `NativeRaw.decode(path,maxSide)` は読み取り可能なファイルを受け、縦横正数・長辺maxSide以下・RGBA各32bit float・行優先のlinear sRGB画像を返す。alpha=1。カメラWBを基準とし、色温度/色かぶりはその基準への相対補正。maxSideは256..2048へ制限、入力寸法/画素数/ファイルサイズを検証する。失敗時は例外、途中結果を返さない。バッファはJava所有のdirect ByteBuffer、共有のnativeポインタを持たない。
- 初期実験はLibRawのhalf-size現像と長辺2048px以下の縮小を許容。デモザイク/色変換段階で失ったハイライトは回復保証しない。商用品質・Adobe Color初期発色と同一ではない。
- 出力は同一の調整済み画素からsRGB JPEG、長辺2048px以下。保存前に寸法と「実験」の表示。MediaStoreの新規pending出力へ書き、書込と公開成功後のみ完了。失敗/中止は今回の不完全出力を削除し、原本や既存出力を変更しない。EXIF個人情報は継承しない。

## パラメーターと操作

- WB: 相対温度/色かぶり。質感: テクスチャ/明瞭度、かすみの除去。トーン: 端点固定、制御点1つ。明るさ: 露光EV/中間調明度。明暗: ハイライト/シャドウ＋コントラスト。白黒: 白/黒。カラー: 彩度/バイブランス。
- 面・右辺・下辺は同一状態を更新。面は両軸、右辺は縦軸のみ、下辺は横軸のみ。中立値/範囲/有限値をモデルが保証。タブ切替では値を保持。現在タブの初期化だけを行える。
- 彩度MAXは表示専用。WB以外への移動・背景化・保存時は解除。ユーザーの彩度値や保存結果を変えない。補正前表示も表示専用。
- 画面の操作順と画素の計算順は別。全パラメーターを状態として保存し、同じ状態なら操作順によらず同じ結果。
- 写真はピンチ・パン・全体表示が可能。変更を戻す際も拡大位置を保つ。未保存の変更はBackで破棄確認。ロード/保存中の離脱はキャンセルし、後から画面を更新しない。

## 非同期・性能

- 読込と保存はUIスレッド外。調整処理はGLスレッドで最新状態だけ描画、古い要求を溜めない。停止/破棄時は所有リソースを解放。ライフサイクルで再読込/状態復元を行う。
- 調整開始→画面への反映、RAW読込、保存開始→公開完了をmsで計測。寸法・形式・成功/失敗のみログへ記録し、写真の識別子を含めない。
- UI参照HTML完成まではAndroidのUI実装へ進まない。native読込・モデル・処理基盤は独立して準備できる。

## 検証計画と未確認

単体: 範囲・中立・片軸不変・彩度MAX出力除外。合成実機: 全タブ/スライダー/面/カーブ/比較/保存/再読/失敗/中止。実RAW: GR DNGとOM ORFを読み出し、表示・拡大・調整・JPEG別保存・原本hash不変。初期実験では端末内で行い写真はリポジトリへ追加しない。Claude参照との独立UI評価、Cold Review、Security Review。状態モデル・合成GPU/2DUI・Monoの処理基盤・DNG/ORFの実RAW展開とJPEGエンコード・実モノクロRAWでの読込/連続調整/別保存/原本hash不変は確認済み。更新後UI・本体導線・独立UI/Cold/Security Reviewは未確認。実測の条件と結果はissueの工程記録を参照する。

## 写真を観察しながら調整するUIの契約

- 目的: UIの数値や枠より写真の変化に集中して現像できる。
- 機能: 写真を上下の最小操作列を除く画面全域へフィット表示し、同一座標の透明な2DUIで全7タブの各ペアを操作する。
- 不変条件: 2DUIの枠・背景・目盛り・数値・軸名は通常時も操作中も描かず、半透明のカーソルだけを写真上へ描く。右辺・下辺の片軸操作は同じ値へ同期。軸の読み上げ名とAXの値変更操作は保持する。補助操作は写真の占有領域を縮めない。
- 事前条件: 写真の読み込みと初回表示が完了している。
- 事後条件: 操作は対象パラメーターだけを変え、タブ切替でカーソル領域の位置・寸法が動かず、写真のズーム/パン位置と他タブの値を保つ。2本指はパラメーター変更を止めてピンチズームへ渡す。指を離してもカーソルは半透明で残る。全体表示では元の縦横比を保ち切り抜かない。
- 明るさ=露出/明度、明暗=ハイライト/シャドウ＋コントラスト、白黒=白/黒をそれぞれ独立したタブにする。初期化は現在タブだけ。
- Monoはカラータブの保存対象トグル。明暗補正後の輝度からモノクロ化し、HSL色相260度/彩度11%/輝度+2ポイントを付与する。最後に彩度/バイブランスでこの色調の強さを調整できる。色相の表現と見え方の呼び名は混同せず、数値を優先する。オフで元のカラー調整値を復元し、オン/オフで他の値を変更しない。彩度MAX/補正前は引き続き保存対象外。
- 状態: 利用者指定の合意済み要件を上記の操作契約へ具体化。最終寸法・補助操作の配置はClaudeの更新HTML完成後に確定し、Android UIを実装する。

## 応答性の契約

- 目的: 連続して動かしても写真の変化を観察でき、操作の重さを減らす。
- 事前条件: RAW読込済みで同じ入力寸法・調整値・連続ジェスチャー条件を使用し、動画再生/PiPを停止する。
- 計測: パラメーター要求に単調増加IDとelapsedRealtimeNanosを割り当て、画面に適用したIDのViewTreeObserver frame commitまでを関連づける。描画完了、UI適用、frame commitを区別し、GPU時間だけを入力応答と呼ばない。frame commitはディスプレイ走査完了を保証しない。匿名のID/時間/寸法だけをdebug時に記録する。
- 不変条件: 処理中は最新状態へまとめ、表示できる中間結果は単調な順で提示する。連続入力のたびに結果を破棄して操作が止まるまで写真が更新されない状態を作らない。最後に指を離した値を必ず表示する。画像処理の数値と保存結果を速度改善だけで変更しない。
- 検証: 改善前/後の同条件の中央値・p95、連続入力中に反映したフレーム数、指を離して最終値までの時間を比較する。実写真と合成写真は区別。現時点で数値目標は未確定、実測で判断する。

## 本体への導線

利用者は実験版を操作してLoupe本体への組み込みを承認済み。本体の写真編集入口から内蔵現像を通常タップで開けるようにし、外部エディターは別操作で残す。既存の共有・写真管理データを維持し、元のRAWを変更しない。インストール時は本体の現在版と今回版を確認してデータ保持で更新する。

## Claude参照HTMLの具体化

参照は `design/loupe-raw-editor-overlay.html`。HTMLの取得・構造確認済み、描画確認と元S08との直接比較は未完了で、Androidの新UIは未実装。

- 上56dp、補助操作56dp、下タブ64dp＋下余白20dp。写真は残りを全体フィットで使用する。400×844では写真400×648dp、400×640では400×444dp。
- 操作面Sは `min(画面幅-72,写真領域の高さ-72)` dp、面＋右/下帯の全体（S+56dp）を写真領域中央に配置。外側8dp以上、間8dp、各帯48dp。400dp幅ではS=328dp。タブによって位置/寸法を変えない。
- カーソルは直径28dp・線2dp。待機時は線55%/内側12%/外側黒30%、操作中は線95%/内側25%/外側黒50%。通常時も操作中も枠・軸・数値・カーブ線を描かない。キーボード/AXフォーカスだけ2dp枠を出す。
- 2本目の指で、そのジェスチャーの最初の指を置く前の値へ戻し、全ての指を離すまで写真のピンチ/2本指パンへ切り替える。倍率1..4。2DUIは拡大した写真とは別の画面座標で固定。
- タブ幅 `max(56dp,画面幅/7)`、高さ64dp・アイコン24dp・12sp。392dp未満だけ横スクロール。選択タブを見える位置へ寄せ、文字を省略・縮小しない。
- 補助行は全タブ同じ56dp。WB彩度MAX、質感かすみ、明暗コントラスト、カラーモノクロ。右端に48dpの拡大/全体操作。上にヘルプを置き、そこだけ軸名・値・使い方を確認できる。
- 下位の元写真画面では編集の通常タップを内蔵へ、外部編集を長押し/AXカスタム操作/情報シートへ移す。原本コピー準備と中止/画面離脱/失敗/再試行の保全は両方の導線で維持する。
